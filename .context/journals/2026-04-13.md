The smoking-gun diagnostic was the FastSAC eval Q bias: **0.10** (Q mean 9.07 vs MC mean 9.19). On a long-horizon DR'd task with 1000-step episodes (= heavy timeout rate), pre-fix this would have shown systematic underestimation with negative Q-bias. ## Lessons

- **Q bias is the cleanest diagnostic for truncation handling.** On long-horizon tasks, post-fix Q bias should be near zero. If it's negative-biased, the fix isn't applied or the wrapper isn't populating `info["truncation"]`. Add to the smoke-test checklist.
- **CheckpointManager "best" excludes final eval.** Either fix the manager to also check the final eval against `best_eval`, or just always take `max(best_in_loop, final_eval)` when reading benchmarks. Lower-priority code cleanup.
- **FlashSAC needs more Warp memory headroom.** Larger networks → JAX heap eats more of the 0.7 fraction → less left for Warp graph capture. `XLA_CLIENT_MEM_FRACTION=0.55` is the FlashSAC-specific default. Worth bumping in `train_flashsac.py`'s `os.environ.setdefault` so users don't hit the OOM.
- **TODO line items can lie about preset values.** `# uses preset 10M` was wrong (preset is 100M). When writing TODO commands, paste the explicit `--total-timesteps` rather than relying on memorized preset values.
- **Velocity "kick" vs force "push" is universal terminology drift.** Across legged_gym/Isaac Lab/RSL-RL/Playground, everyone calls it a "kick" but implements it as direct `qvel` injection (mass-invariant, deterministic). Calling it a "force" would be wrong; calling it a "velocity perturbation" would be pedantically correct; calling it a "kick" is field convention. Code comment/var name in `go2_warp_joystick.py:304-313` uses "kick" + "push_vel" interchangeably — slight inconsistency, low priority.
