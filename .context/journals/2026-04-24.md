# 2026-04-24 — Critic-norm + reward-norm persistence + schema-from-ckpt + TD-MPC2 port

Three correctness fixes shipped today, all in the same theme: state that needs to persist across train→deploy or train→resume boundaries was getting silently dropped. Plus the TD-MPC2 algorithm port (Phases A-I) landed end-of-day on a separate branch.

## Privileged-obs normalization (commit 4562307, 1c6ed7d)

**Was:** off-policy with `has_privileged=True` passed raw critic_obs to algos and `q_fn` eval. On-policy maintained `critic_norm_state` in-process but never persisted to checkpoint — resume reset stats. Net: silent divergence between on/off-policy paths and across resume.

**Fix:** unified critic-norm primitives in `obs_pipeline.py` (`init_critic_norm_state`, `update_critic_stats`, `normalize_critic`, `make_critic_norm_fn`). Off-policy threads `critic_norm_state` through update + save/load + q_fn lambdas. On-policy persists via ckpt. `checkpointing.py` adds backwards-compat fallback for pre-fix ckpts (orbax try/retry on schema mismatch).

**Verified:** 13 new tests (11 obs_pipeline + 2 checkpoint), 80 tests pass total. Smoke runs Go2WarpJoystickFlat 2M @ 256 envs:
- FastSAC: eval **273.2 ± 3.7**, Q stable ~8.8.
- PPO: return 1.4→165, VLoss stable.

**Independently reviewed.** Reviewer found 2 blockers I'd missed: orbax strict-schema fails on missing key (need try/retry), and resumed on-policy semantics with bandaid-trained ckpts. Both fixed before merge. Reviewer also caught my missed callsite — `q_fn` eval lambda was passing raw privileged_state to `get_q_value`. Fixed.

**Follow-up filed:** re-run PPO4 bongo baseline (eval 46.9, pre-fix) with corrected critic-norm to validate ContractionPPO comparisons.

## FlashSAC reward_norm_state persistence (commit 6a17f9b, 3fe429b)

**Was:** `reward_norm_state` (G_r, G_r_max, G_var, G_count) lived as a module-local variable in `train_flashsac.py:158`. Not in `TrainingState`. Not in ckpt. Resume reset stats — `G_r_max` is monotonic running max, may never recover for near-optimal policies; denominator drops; rewards briefly scaled UP by up to G_max×; can push Q-targets outside C51 support.

**Fix:** fold `RewardNormState` into `TrainingState` (parallels `noise_state` field). Orbax serializes via existing `training_state` entry — zero changes to checkpointing/eval_runner. Pattern matches reference Holiday-Robot/FlashSAC (`reward_normalizer.pt` is a first-class artifact there).

**Verified — but my first verification was sloppy.** I ran a CartpoleBalance smoke that showed RewScale ~8.6 post-resume (matching pre-resume ~8.4) and called the fix verified. User pushed back ("smell sus"), independent reviewer confirmed: 20k steps of re-accumulation post-resume could land on a similar denominator regardless of persistence. Test was confounded.

**Real verification:** loaded the checkpoint and inspected `reward_norm_state.G_count` directly:
- `G_count = 499,968` ≈ 7,812 outer_steps × 64 envs (matches 500k env steps exactly; fresh init = 0).
- `G_r_max = 33.28` (fresh = 0).
- Computed RewScale from ckpt = 8.4318, matches pre-resume log line 8.435 to 3 decimals.

Lesson learned: signal-based verification of state persistence is fragile when the signal is subject to fast re-accumulation. Inspect the state directly.

**Follow-up filed (🔥 high priority):** post-resume eval drop 996→747 on CartpoleBalance is NOT from reward_norm_state (now verified persisted). Audit identified: `JaxReplayBuffer` has zero save/load methods. Empty buffer on resume → 10k steps of random-uniform actions → policy degrades during initial gradient updates on OOD batch. Reference repo persists buffer. Three fixes ranked in TODO; cheapest is "skip random warmup on resume" (use restored policy to collect data instead).

## Deploy schema-from-checkpoint (commit 437f530)

**Was:** `deploy/obs_builder.py` hardcoded the actor obs layout. Only contract sim↔deploy was `obs_dim` (an int). Drift history:
- 2026-03-26: deploy written with `[linvel(zeroed), gyro, gravity, ...]` = 48d.
- 2026-04-10: sim removed `linvel` from actor (45d). Deploy not touched.
- (Later, commit 62ec4ae mislabeled "docs:"): sim added `accelerometer` to actor (back to 48d, different content). Deploy not touched.

For ~14 days, every Go2 ckpt would have failed sim2real silently — deploy fed real `gyro` data into the slot the policy interpreted as `accelerometer`. Total dim 48 == 48 → no warning.

**Fix:** treat the obs schema as part of the checkpoint. `save_checkpoint` writes `meta.json["obs_schema"]["state"]` = ordered term-name list (extracted via new `schema_from_obs_groups` helper, resolving `IncludeGroup` recursively). Deploy `ObsBuilder.from_checkpoint(ckpt_dir)` factory reads it and composes obs in saved order via a sensor-fetcher registry keyed by term name. Unknown term → clear ValueError pointing at the file to edit. Backward-compat: ckpts without `obs_schema` fall back to a printed default schema.

**Verified end-to-end on CPU:** fake `_obs_groups` → schema → meta.json → `ObsBuilder.from_checkpoint` → 48d obs with gyro at [0:3], accel at [3:6]. 9 deploy tests green covering default, drop_accel, reorder, unknown-term, with/without schema, schema extractor IncludeGroup recursion.

**Bonus cleanup:** dropped dead `VelocityEstimator` from `deploy/deploy_go2.py` (linvel hasn't been in actor obs for years). Added `WarpJoystickNoAccel` ablation env on the sim side (registered as `Go2WarpJoystickFlatNoAccel`); deploy auto-syncs via schema, no special case needed.

**Origin question driven by user.** I'd initially proposed a hardcoded patch (just sync deploy to current sim layout). User pushed: "shouldn't deploy infer from ckpt config?" That's the real fix. The patch I almost shipped would have prevented today's failure but not the next one. Schema-from-ckpt makes the failure mode structurally impossible.

## Pyramid_up L1 root cause (commit 4451286)

GPU was busy mid-day, so I burned a no-GPU window auditing v16 trajectory data (videos/v16/pyramid_up_L1_traj.npz). Findings:

- Robot spawns correctly on outer-x edge of tile, yaw=π facing tile center.
- Tracks `cmd_vx=+0.6` body-frame correctly, walks ~0.76m in 1.4s.
- Reaches edge of ring 1 (tile-local x≈3.84). Ring 1 step at L1 = `0.2 × max_step_height = 0.08m` (8 cm).
- Robot has no climbing gait — walks straight into the step face. Torso pitch spikes (qvel_ang_y negative), then roll/yaw tumble. `base_contact` fires → termination at t=70.

Why it stalls at mean_level <0.4: L0 has step_h=0 (fully flat). L0→L1 jumps from 0 to 8cm with no shaping for foot-lift. Demote-on-fall sends env back to L0, which has nothing to climb → oscillates L0↔L1.

Fix candidates documented in `lessons/terrain_curriculum.md` §pyramid_up L1 failure mode and `TODO.md`. Cheapest: quadratic difficulty curve in `primitives.py:233`, makes L1 = 16mm. Not implemented today — the curriculum was already shipped, this is a future iteration.

## Test-time validation playbook (commit d554b96)

End-of-day debug session: user got hardware accel reading working, ran the most recent FastSAC ckpt on hardware, captured obs printout to `.temp/obs_prinout.txt`. First obs at "stance" had:

- gyro ≈ 0 ✓
- accel = `[0.77, -0.28, +9.53]` ≈ MuJoCo specific-force convention, magnitude ~g ✓
- gravity = **`[0.07, 0.82, 0.57]`** ❌ (should be `[0,0,-1]` upright)

Both `accel_z` and `gravity_z` positive at t=0 → cross-check fails (specific force should oppose projected gravity). Either quat convention mismatch, IMU mount frame mismatch, or robot wasn't actually upright at log start.

Cascade played out as predicted: line 2 actions saturated (raw actions ±0.99 across joints), real gyro/accel exploded by line 5. Classic "bad-from-t=0 → policy saturates → robot flails → OOD spiral" pattern.

Built `deploy/test_time_validate.md` from this session: pre-flight raw-sensor logging, stance obs expectations, four cross-checks (||grav||, ||accel||, sign opposition, joint_pos_offset all-small), geometric decoder for gravity → robot orientation, schema check workflow, cascade pattern recognition, lift-a-leg joint remap test, PD gain sanity, obs-norm sanity, 10-item TL;DR checklist. Use before sending velocity commands every fresh deploy. Catches ~80% of sim2real silent failures from a single stance obs.

## Theme

All three fixes share a shape: **state that lives across some boundary needs to be serialized at the boundary, not reconstructed by convention on the other side.**

- Critic-norm: saved with the ckpt, read on resume.
- Reward-norm: saved with the ckpt, read on resume.
- Obs schema: saved with the ckpt, read by deploy.

When the producer and consumer of a piece of state are decoupled in time or in code, "we'll just remember to update both" is not a strategy. It's not even a hope. We had three independent silent-divergence bugs from this anti-pattern, all caught in one day after one was tugged on.

## Push-T letter matrix V2 — N=10 dense KPs fix the zero-pad leak (commits 7dab090, af54652, d6fa576)

**Was (V1, N=11 zero-pad):** 5×4 cross-shape matrix on letter shapes (T/L/K/S + DR). Specialists hit own-shape 80-89% sto cov but **off-diagonals collapsed to ~0%**. DR 5M row-mean 32.9% sto / 24.8% det — well below the prior 5d-state DR baseline of 62.6%. L and K specialists also showed late-training critic blowup; DR collapsed late too (Q1L 2.5e+03, alpha 0.098 runaway).

**Hypothesis:** keypoint obs was 27d = 5d state + 22d KPs zero-padded to MAX=11. Per-shape KP counts {T:4, L:3, K:5, S:11} mean **each shape has a unique number of trailing zero slots**, which after `NormalizeObsWrapper` (low=0, high=512) maps to a unique number of trailing −1.0 slots — a literal one-hot shape ID encoded in the pad pattern. Policy learns strategies indexed by pad pattern; off-diagonal evals show OOD pad → policy freezes.

**Diagnostics (D1, D2):**
- D1 (eval-time KP ablation): T-specialist on tee → blank KPs to 0 or −1 → cov drops 89% → 0.7%. KPs are load-bearing, policy isn't ignoring them. Brittle to OOD obs patterns.
- D2 (math): post-norm pad value is exactly −1.0, deterministic per shape. Linear probe trivially identifies shape.

**Fix (V2, N=10 dense):** redesigned KPs to be exactly N=10 per shape via multi-branch arc-length sampling along skeleton polylines (T: 5 bar + 5 stem; L: 5 vert + 5 foot; K: 4 bar + junction + 3 upper + 2 lower; S: 10 along smooth midline). Obs becomes 25d = 5d state + 20d dense KPs, **no padding ever**. Same training config otherwise.

**Result:**
- DR row-mean **32.9% → 73.9% sto / 24.8% → 57.8% det** (+41 / +33 pp). **Beats 5d-state DR baseline by 11pp.**
- Specialists own-cov also up: T 89.4 → 90.6, L 81.8 → 89.6, K 80.5 → **93.9**, S 84.4 → 89.1. K's +13.4 own-shape jump confirms pad was hurting own-shape learning, not just transfer.
- DR 5M ran cleanly to completion, no late critic collapse (V2 final Q1L ≈ 2 vs V1 ≈ 2500). The collapse was downstream of the leak — multimodal target distribution was effectively "one policy per pad pattern."
- L specialist V2 also stable to 2M (Q1L ≈ 2 final, not the V1 spike to 1e+02).

**Lesson:** if a "shape-agnostic" obs has any per-shape variability (slot counts, pad patterns, dim scaling), a deep policy will find the leak and condition on it. Make the obs structurally identical across shapes — same dims, same value distribution, no per-shape signature — or the abstraction is fiction.

**Workflow note:** user explicitly required "render KPs and let me give feedback before committing" after I'd previously messed up T scale + S point distribution. Two render-iterate cycles before training: caught duplicates from the Euler-tour polyline approach, switched to multi-branch proportional sampling.

**Artifacts:**
- Study: `.context/studies/2026-04-22_pusht_letter_matrix.md` (V1 + V2 sections, both matrices, root cause, deferred next steps).
- V2 ckpts: `checkpoints/20260424_124411` (T), `_131444` (L), `_134029` (K), `_164632` (S retry — first attempt crashed silently at 600k), `_143821` (DR 5M).
- Visual grid: `.context/studies/assets/2026-04-22_pusht_letters/letter_matrix_n10_grid_sto.png`.

**Open follow-ups (deferred):**
- Held-out unseen letters (M/W/U/V) — true zero-shot test. V2 DR should generalize if KP representation is shape-agnostic.
- Set-transformer / masked attention over variable-N KPs — avoids fixed-N constraint, may generalize further.

# TD-MPC2 port (Phases A-I complete)

## What happened

Ported TD-MPC2 (Hansen et al. 2024, `nicklashansen/tdmpc2`) to the JAX/Flax framework via subagent-driven development. Branch: `tdmpc2-impl` (worktree at `.worktrees/tdmpc2-impl/`). All code committed, all unit/smoke tests passing.

## Pipeline summary

Brainstorm → spec (5 review iterations caught 14+ silent-failure bugs) → plan (3 review iterations) → subagent-driven-development (35+ task dispatches).

### Spec review rounds (what got caught)
1. Iter 1 (14 issues): `consistency_coef=1` vs 20 (20× off); SAC auto-α vs fixed `entropy_coef=1e-4`; target-encoder vs online-sg consistency target.
2. Iter 2 (3 residuals): task_emb param group, squash numerical floor, acceptance criteria gaps.
3. Iter 3 (1 critical + 7 important): `mask_h` wrongly applied to reward/value losses; Q-scale missing `min=1.` clamp; dead config params.
4. Iter 4 (**3 critical**): **policy loss entropy sign flipped** (would cause deterministic collapse); **TD target used nonexistent `dynamics_target`** (should be `encoder_online(obs[h+1])`); Q-scale input misread.
5. Iter 5 (0 critical): minor polish — decode-then-min ordering clarity, `a_next_h` is reparameterized sample.

## Key design decisions

- **B-with-seams, not C:** single-task P1 implementation with forward-compatibility seams for later multi-task extension. `task_id: Optional[...] = None` threaded through all nets, `num_tasks=1` in config, etc.
- **Benchmarks:** DMC first (CheetahRun, HumanoidRun, AcrobotSwingup), then Go2 (P2, separate plan), PushT deferred (P3).
- **Go2 obs:** state-only default (symmetric encoder); revisit if underperforms FastSAC.
- **Collect `num_envs=8`** (not 1 per source) — throughput deviation documented, A/B planned.
- **Eval runs both MPPI + prior modes** — gap metric is load-bearing diagnostic for bottleneck analysis.
- **Checkpoints split:** `actor_params.npz` (deployable policy only) + `world_model_params.npz` (full WM for MPPI at inference).

## Load-bearing details (all verified against source)

- `consistency_coef=20`, `reward_coef=0.1`, `value_coef=0.1`, `entropy_coef=1e-4` (fixed, not auto-tune)
- `/H` normalization on consistency + reward; `/(H·num_q)` on value; rho discount `rho^h` per step
- All three world-model losses **UNMASKED** — `(1-terminated)` factor appears ONLY in TD-target bootstrap
- TD target: `encoder_online(obs[h+1])` + online policy sample + target Q **min-of-2** with **decode-then-min** ordering
- Policy loss: `L = -(1/(H+1)) · Σ rho^h · (entropy_coef·scaled_entropy + qs_scaled)` — outer negative, + inside
- scaled_entropy uses **pre-squash** log_prob
- Squash Jacobian: `log(relu(1 - a²) + 1e-6)` — the floor prevents NaN at saturation
- MPPI action: **single-elite** Gumbel sample (NOT elite-weighted mean); noise `std[0]·ε`
- Pi-seed trajectories: `horizon` samples, `horizon-1` dynamics advances
- `_prev_mean` per-env shift + zero on episode reset (vectorized over `num_envs`)
- Q-scale `range = max(p95-p5, 1.0)` clamp before EMA
- Single Adam + `multi_transform` for encoder-scaled LR (`lr·0.3`)
- Target EMA on encoder/dynamics/reward/Q only (NOT policy)
- Per-episode slice sampling in buffer (episode_id match across H+1 window)

**Critical perf bug found post-merge** (commit a6d41e4): `make_plan_batched` returned raw `jax.vmap(plan, ...)` — vmap batch-transforms but doesn't JIT. Every MPPI call retraced full Python compute graph. Cached call ~789ms on CPU; under GPU contention ballooned to 10-30s/call × 4 outer iters → H3 smoke timed out at 15min for what should take ~1min. Fix: `jax.jit(vmapped, static_argnums=(4, 6))` with cfg + eval_mode static. 4000× speedup on cached calls. **Load-bearing for production training**: 1M env steps × 789ms = 9+ days of trace overhead before fix; now 200s.
