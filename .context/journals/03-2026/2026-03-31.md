# 2026-03-31 — Config Architecture Cleanup

## What happened

Repo config audit prompted by accumulating complexity in `jax_rl/configs/`. Researched how CleanRL, SB3, Brax, RSL-RL, rl_games, and JaxRL handle multi-algo configs.

## Key decisions

1. **FastSACConfig no longer inherits from SACConfig.** Made standalone with paper-correct defaults. The inheritance was dangerous: 9 of 14 inherited fields had wrong defaults for FastSAC (tau=0.005 vs 0.125, batch=512 vs 8192, activation=relu vs swish, etc.). Bare `FastSACConfig()` silently produced SAC defaults — the exact footgun that caused the tau=0.005 NaN divergence on HumanoidRun.

2. **Flat per-algo configs is the right pattern.** SAC/TD3/FastSAC/FastTD3 share field *names* but not field *values*. An `OffPolicyConfig` base class would have the same problem — what default does tau get? Any choice is wrong for half the children.

3. **Deleted QHeadConfig and ValueHeadConfig.** QHeadConfig was never instantiated — Q heads get params directly from algo configs. ValueHeadConfig was an empty dataclass (`pass`) threaded through PPO but carrying zero information.

4. **Left the two-pattern coexistence alone.** PPO uses sub-configs (EncoderConfig → MlpEncoder), off-policy algos pass raw params. Both work. Will revisit when vision RL forces the question.

## Files changed

- `jax_rl/configs/fast_sac_config.py` — standalone dataclass, paper defaults
- `jax_rl/configs/networks_config.py` — removed QHeadConfig, ValueHeadConfig
- `jax_rl/configs/ppo_config.py` — removed value_head field
- `jax_rl/networks/heads/value.py` — ValueHead no longer takes config
- `jax_rl/networks/builders.py` — VCritic simplified
- `jax_rl/algos/ppo.py` — updated VCritic construction
- Tests updated to match

## Session 2 — Warp env review + future planning

### Topics covered

1. **Go2 Warp observation space review** — confirmed 48d actor (linvel, gyro, gravity, joint angles, joint vel, last action, command) + 122d privileged critic (adds unnoised sensors, actuator forces, contact info, external forces).

2. **Muon optimizer research** — investigated `optax.contrib.muon` for future use. Key findings:
   - Already available in optax 0.2.6, drop-in `GradientTransformation`
   - Auto-routes 2D weight matrices → Muon (Newton-Schulz orthogonalization), biases/norms → internal AdamW
   - JITs cleanly (uses `lax.fori_loop(unroll=True)`)
   - **RL caveat:** zero published RL benchmarks. Non-stationary targets + small 256×256 MLPs are untested territory. Recommendation: actor-only Muon, keep critic on AdamW when experimenting.
   - Our optimizer decoupling pattern (algos take optimizers as constructor args) makes this a one-line swap in the train script

3. **ONNX version** — confirmed not relevant. Deploy pipeline uses numpy inference at 50Hz. Any recent onnxruntime (1.14+) would handle our MLP if needed later.
