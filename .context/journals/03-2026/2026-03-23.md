# 2026-03-23 — Go2 Environment Implementation

## What we did

### Go2Env — first custom locomotion env
Implemented Go2 joystick velocity tracking env following Playground's Go1 pattern.

**Files created:**
- `jax_rl/envs/locomotion/go2_joystick.py` — Joystick task (main env)
- `jax_rl/envs/locomotion/go2_base.py` — Go2Env base class (sensor helpers, PD setup)
- `jax_rl/envs/locomotion/go2_constants.py` — Go2-specific names/paths
- `jax_rl/envs/locomotion/xmls/go2_scene_flat.xml` — Scene XML (floor + missing sensors)
- `tests/test_go2_env.py` — 10 tests (loads, steps, shapes, termination, integration)

**Key design decisions:**
- Subclasses Playground's `MjxEnv` directly (same as Go1Env)
- Scene XML includes Menagerie's `go2_mjx.xml` and adds missing sensors (local_linvel, upvector, foot contact, foot position/velocity)
- Returns **flat 31-dim obs** (not dict like Go1) — compatible with our training pipeline without modifications
- Kp=20, Kd=0.5 (Unitree official)
- action_scale=0.25 (Unitree official)
- legged_gym reward weights (tracking, stability, regularization, feet)

**Obs space (31 dims, per plan):**
- command (3): vx, vy, yaw_rate
- yaw_rate (1): gyro z
- projected_gravity (3): body frame
- joint_pos_offset (12): q - q_default
- last_action (12): previous step

No linvel (not measurable on hardware). Frame stacking to be added in the env later.

### env_setup.py — unified registry loading
Changed `make_envs` from `dm_control_suite.load()` to `registry.load()` (Playground's unified loader). Registered Go2 env via `locomotion.register_environment()`. Now `--env Go2JoystickFlat` works in any training script, same as `--env CheetahRun`.

**Regression verified:** CheetahRun still loads correctly through registry.

### Go2 PPO preset
Added `Go2JoystickFlat` preset to env_presets.py: 1024 envs, gamma=0.97, 20M steps.

### Test results
- 10/10 Go2 env tests pass (loads, steps, shapes, termination, batched integration, DM Control Suite regression)

### Go2/Go1 differences documented
| Aspect | Go1 (Playground) | Go2 (our env) |
|---|---|---|
| Root body | `trunk` | `base` |
| Foot sites | `FL`, `FR`, `RL`, `RR` | `FL_foot`, `FR_foot`, `RL_foot`, `RR_foot` |
| Actuator type | `position` | `general` (biastype=affine) |
| Default Kp | 35 | 20 (Unitree official) |
| Default height | 0.278m | 0.27m |
| Obs format | dict (`state` + `privileged_state`) | flat 31-dim array |

### Open question RESOLVED
**Can Playground's MjxEnv support custom reward functions cleanly?** YES. Go1's Joystick env shows the exact pattern — `_get_reward()` returns a dict of terms, weighted by config. Fully overridable. No hacks needed.

### PPO smoke test — PASSED
64 envs, 500k steps, seed 42.
- **Eval return: 18.5 ± 5.8 [9, 30]** — robot is learning, not falling
- No NaN, no crashes
- 3.5k sps (64 envs, GPU shared with nuclio 2.8GB process)
- Checkpoint: `checkpoints/20260323_001717_go2joystickflat_seed42`

Could not run at 1024 envs — nuclio process (PID 1130821) using 2.8GB GPU. 64 envs is a valid smoke test but not representative of final performance.

### PPO debugging — robot stands/shuffles but won't walk

Extensive debugging session after the smoke test. Robot never learned to track velocity commands.

**Runs:** 7 training runs (seeds 42-300), varied reward_scaling, reward weights, obs dims, network size. Best result: eval ~50 with 4x tracking reward (shuffling, no foot lift).

**Root cause analysis (first-principles):** see `.context/go2_ppo_debugging.md` for full triage. Key findings:
- `reward_scaling` was a red herring — advantage normalization makes policy gradient scale-invariant
- Missing linvel in obs (policy can't sense body velocity)
- No privileged_state for critic (Brax critic sees 123d ground truth, ours sees 45d noisy obs)
- Minibatch size 640 vs 5120 — compensatable by training longer

**Next:** Add linvel to obs (45→48d), add privileged_state dict for critic, retrain.

### Brax PPO A/B test — env is fine, training budget insufficient
Ran Brax's own PPO on both Go1 and Go2 at 512 envs, 50M steps:
- **Go1 Brax PPO:** eval 21.7 at 50M (matches published curve — Go1 peaks at ~25 at 100M)
- **Go2 Brax PPO:** eval 17.9 at 50M
- **Our PPO Go2:** eval 9.0 at 50M (2x worse sample efficiency)

The env produces correct rewards — both Brax and our PPO show learning curves. Neither Go1 nor Go2 walks at 50M steps (paper needs 100-200M).

### Contact physics discovery — Go2 feet are marshmallow-soft
Go2 Menagerie MJCF uses solimp=0.015 (extremely soft foot contacts) vs Go1's solimp=0.9 (firm). Fixed by overriding in go2_base.py to match Go1 values.

### Wall-clock profiling — Python collect loop is the bottleneck
Our PPO is 5x slower wall-clock than Brax (47 min vs 10 min for 50M steps at 512 envs). Root cause: Python-level rollout loop forces 87x overhead on env.step due to GPU pipeline sync at every step.

```
Pure env.step (512 envs, 20 steps): 0.111s → 92,000 sps
Python collect loop (same):         9.729s → 1,053 sps
```

Fix: JIT the collect phase into `lax.scan` (same as Brax). Major refactor of train_ppo.py.
