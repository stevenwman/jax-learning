# 2026-03-13 — CheetahRun HP Tuning, Config Refactor, Tooling

## What we did

### CheetahRun hyperparameter debugging
- Diagnosed entropy growing unboundedly (9→16+) with `entropy_coef=0.001` — policy too noisy, returns stuck at ~248
- Set `entropy_coef=0.0` → returns jumped to 503 (10M), then 666 (20M)
- Added linear LR annealing (`optax.linear_schedule` to 0). Result: 615-633 — worse than no annealing (666). LR decayed too aggressively, policy froze in last 25% of training (clip_fraction dropped to 0.017)
- Switched to env preset HPs (2048 envs, lr=1e-3, num_epochs=16, num_steps=30, reward_scaling=10) → **826 avg return, 896 max at 20M steps**. Passed ≥700 target that the paper said needed 60M steps
- Lesson: the bottleneck was HP config, not training budget. More envs + shorter rollouts + higher LR + more epochs + reward scaling made the difference

### Config architecture refactor
- **Problem:** `train()` had a bloated signature with atomic HP args. `TrainConfig` duplicated PPO-specific fields (`clip_eps`, `entropy_coef`, `num_epochs`, etc.) that won't make sense for SAC
- **Solution:** Nested algo config — `TrainConfig.ppo: PPOConfig | None`. Shared RL params (`gamma`) stay on `TrainConfig`, algo-specific params (`clip_eps`, `entropy_coef`, `gae_lambda`, `num_epochs`) live in `PPOConfig`
- Created `env_presets.py` with per-env `TrainConfig` instances containing nested `PPOConfig`
- `train()` now takes `cfg: TrainConfig, seed: int` — clean interface
- CLI overrides for PPO params route through `dataclasses.replace(cfg.ppo, ...)`

### Optimizer decoupling
- Moved optimizer construction out of PPO into train.py
- PPO takes `actor_optimizer` and `critic_optimizer` as constructor args
- Enables future optimizer swaps (Muon, Shampoo) without touching algorithm code

### Orbax checkpointing + video recording
- Timestamped checkpoint dirs with `meta.json` (env config) + `metrics.csv` (training curves)
- `record_video.py` — two-phase approach: `jax.lax.scan` rollout on GPU, `env.render()` on CPU
- Fixed `checkpointer.wait_until_finished()` for async write safety

### Fixed stale imports
- `jax_rl/algos/__init__.py` still imported deleted `ppo.py` → updated to `ppo_scan`

## Key learnings
- Entropy bonus is env-dependent: CartpoleBalance wants 0.01, CheetahRun wants 0.0
- LR annealing to 0 can hurt if training budget is tight — consider annealing to a floor instead
- Config design: nest algo-specific configs, keep shared params at the training level
- Diagnostic signals: monotonically growing entropy = entropy bonus dominating; PLoss→0 + high clip = needs LR annealing
