# 2026-04-07 — FlashSAC JAX Port

## Paper Review

Read Kim et al. "FlashSAC: Fast and Stable Off-Policy RL for High-Dimensional Robot Control" (arXiv:2604.04539, April 2026). Key innovations over our FastSAC:

- **Inverted residual blocks** with pre-activation BatchNorm — enables 6-layer networks without instability (condition number drops 5-10x)
- **Explicit weight normalization** — project Dense kernels to unit norm, BN scale+bias to √D norm after every optimizer step
- **Adaptive reward scaling** — normalize rewards by running return variance, bounds distributional critic support to [-5, 5]
- **Unified entropy target** — σ=0.15 for all tasks (no per-task tuning)
- **Zeta noise repetition** — temporally correlated exploration via power-law repeat lengths
- **Cross-batch (2B) forward** — concat obs+next_obs for shared BN statistics

Paper claims: 20 min sim training → real locomotion (vs PPO 3 hrs). Order-of-magnitude speedup on sim-to-real.

Comparison doc: `.superpowers/specs/flashsac_vs_fastsac_analysis.md`

## Design & Review

5 spec review passes caught 22 issues total. Most impactful catches:
- **Weight norm axis:** Flax kernel is `(in, out)` vs PyTorch `(out, in)` — normalizing `axis=-1` would have silently broken training (need `axis=0`)
- **Target BN stats not copied:** Target critics maintain own running stats via `train=True` forwards. EMA only updates learned params, not buffers.
- **C51 done signal:** FlashSAC uses `terminated` only (not `terminated|truncated`) for bootstrap, while reward normalizer resets on both
- **Update order:** Actor → temp → critic (opposite from FastSAC's critic-first)

Design spec: `.superpowers/specs/2026-04-07-flashsac-port-design.md`

## Key Design Decisions

1. **Standalone `train_flashsac.py`** — not integrated into `train_offpolicy.py`. FlashSAC has too many collection-time differences (noise repetition, reward stat tracking). Integrate later if results are good.
2. **Two separate critics** (not ensembled) — JAX's functional style makes separate `apply()` calls cleaner than fused ensemble ops. Can add `nn.vmap` later if profiling shows it matters.
3. **Reward norm state outside TrainingState** — simpler flow, no JIT boundary issues. Matches how `obs_norm_state` is handled in existing code.
4. **Vectorized noise** (deviation from reference) — per-env independent repeat cycles vs reference's scalar noise. Behavioral change that needs validation.
