## The Bug

User pushed back on rapid HP pivoting ("metrics look impossible, find evidence before fixing"). Investigated `ep_r_avg = -3100` — physically impossible for one episode since per-step reward ∈ [-0.3, 1.5] × 300 steps gives [-90, +450].

Found:
```python
env1 = gym.make("gym_pusht/PushT-v0")
# env1.spec.max_episode_steps == 300 ✓

env2 = PushTEnv(obs_type="state", ...)  # Our direct construction
# env2.spec == None ✗
```

`gym.make()` reads the env registry spec and applies `TimeLimit` automatically. Direct construction bypasses the registry entirely. Our training loop had no episode cap.

**What this broke:**
- Episodes never terminated (success rate 0%, so `terminated=False` always)
- `truncated=False` too, because no TimeLimit
- Q target = `r + γ * V(s')` with `(1-done)=1` forever → bootstraps an unbounded future
- Buffer stored transitions with `truncation=0` even at step 1000+ into a failed attempt
- Critic learned wildly-wrong Q values

**Fix** (one line in `_make_env`):
```python
env = gym.wrappers.TimeLimit(env, max_episode_steps=300)
```

**Impact:** Q1 went from oscillating in [-1400, +500] range to stable at +35. ep_r_avg went from -3100 to +130. Peak coverage 14% → 88%.

## The "0% Success" Red Herring

Digging into the LeRobot 206-demo dataset: **max reward across all 25,650 frames = 0.9489**. No frame in the expert dataset crosses the 0.95 success threshold. Humans playing gym-pusht via teleop don't "solve" the task under the current threshold either.

Our peak sto coverage (0.889) = **94% of human-expert peak (0.9489)**. Published RL-beats-95% results (e.g. DPPO) require BC pretraining + RL fine-tuning. Pure RL from scratch hitting this range is the expected upper bound; we're there.

## Compounding Lessons (end of day)

Five new lessons written to `.context/lessons/manipulation.md`:

1. **TimeLimit is not applied by direct env construction** — one-line fix, 6× performance gain. Check `env.spec.max_episode_steps` before training.
2. **Verify infrastructure before tuning HPs** — my biggest failure. 8 runs tuning on broken infra. Rule: when a metric goes outside its possible range, halt and find the bug. HPs don't fix infra.
3. **95% success threshold on push-T exceeds human teleop** — before declaring "0% success" as failure, check if the metric is achievable by any baseline.
4. **Don't eyeball metrics from rendered video** — claimed "30° yaw error" from screenshot; actual was 4.66°. Write the diagnostic script (2 LOC from env internals), don't stare at pixels.
5. **FastSAC wrong choice for bounded-reward manipulation** — C51 `[v_min, v_max]` atoms don't cover contact_gated Q range. Vanilla SAC works; FastSAC destabilizes.
6. **Combined recipe that works** — keypoint obs + frame_stack + obs-normalization + action_repeat + contact_gated shaping + SAC with specific HPs + TimeLimit. Full stack required; each component ablated.
