# Part 1 — Env-backend refactor (start-of-day)

---

## Why

Two pain points:

1. **`scripts/train_pusht.py` was a 476-line fork of the SAC stack** — its own numpy replay buffer, its own normalization wrapper, its own training loop, its own eval. Adding any non-Playground env (PushT, MetaWorld, eventually IsaacLab) meant copying the whole stack. The off-policy loop in `run_offpolicy_loop` was already env-agnostic Python iteration, but `make_envs(cfg, seed)` hardcoded `pg_registry.load()` so non-MJX envs couldn't reach it.

2. **Labmate portability.** Goal is for someone running IsaacLab to pull this repo and slot their env in without forking. Without a backend abstraction, every new env becomes another `train_<env>.py`.

### Phase 0 — `EnvBundle` Protocol (commit 9273c2b)

Relocated the `EnvBundle` dataclass from `env_setup.py` to its own module `jax_rl/training/env_bundle.py`. Added three fields: `backend_kind: Literal["mjx", "gym", "isaaclab"]`, `num_envs: int`, `render_fn: Optional[Callable]`. MJX path defaults to `backend_kind="mjx"`, no behavior change.

This is pure scaffolding — no new envs, no new behavior. Sets up the dispatch surface for Phases 1-5.

### Phase 1 — Backend registry (commit 2c3f68a)

`jax_rl/training/env_backends/__init__.py` introduces `BACKEND_BUILDERS`, `register_backend(name, builder)`, `detect_backend(env_name)`, `build_env_bundle(cfg, seed)`. Detection rule: `IsaacLab/<...>` → isaaclab, registered gym names → gym, else → mjx.

`mjx_backend.py` houses the relocated MJX code: custom env registration with Playground, the NaN-safe step wrapper (`_make_nan_safe_step`), `make_envs`, `make_mjx_env_bundle`. Self-registers as `"mjx"` at import. `env_setup.py` becomes a thin shim: `make_env_bundle()` dispatches via the registry; `make_envs` and `_make_nan_safe_step` are re-exported for legacy callers (train_ppo*, train_flashsac, test_algo_configs).

### Phase 2 — Gym backend (commit f4ac6ad)

`gym_backend.py`:
- `GymState` dataclass mirroring MJX state surface (`.obs / .reward / .done / .info["truncation"]`) so the off-policy loop works unchanged.
- `make_gym_env_bundle`: builds `gym.vector.{Sync,Async}VectorEnv`, caps `num_envs` at `os.cpu_count()` with a warning.
- `GYM_ENV_FACTORIES` registry; PushT first concrete entry — reads env_kwargs from cfg (obs_type, block_shape, reward_mode, etc.), ports `NormalizeObsWrapper` + `ActionRepeatWrapper` from `train_pusht.py`, adds `gym.wrappers.RescaleAction` for [-1,1] policy → gym action space.
- Self-registers as `"gym"` on import.

Gym needs a Python-loop eval (no `lax.scan`):
- `jax_rl/utils/eval.py`: add `evaluate_gym()` — single-env serial Python loop, same return shape as `evaluate()`. Skips Q-bias diagnostics (gym mostly used for low-dim research; backfill if needed).
- `jax_rl/training/eval_runner.py`: dispatches `evaluate` vs `evaluate_gym` via `TrainContext.backend_kind`.
- `TrainContext` gets a `backend_kind` field (default `"mjx"`); `offpolicy_loop` threads `bundle.backend_kind` into ctx.

`TrainConfig`: add `env_kwargs: dict` field for backend-specific construction details (gym/isaaclab); ignored by mjx.

Smoke: `train_sac --env PushT --total-timesteps 3000` ran warmup → eval → ckpt cleanly.

# Part 2 — TD-MPC2 J4 HumanoidRun debug → paper-band match (late-day)

Continued from 2026-04-25's J3 paper-match. J4 HumanoidRun 1M (seed 0) initially stalled at mppi=8 through step 300k. Two more correctness bugs (Bug A: truncated≠terminated, Bug B: Q dropout off in policy/qscale paths) + one env-parity fix (action_repeat=2) + episode_length=500 unblocked it. Final v3 run: **mppi=556.99 ± 4.06 over 40 episodes** at 1M env steps. Within paper Fig.15 Humanoid Run trajectory band.

## Bugs found and fixed

### Bug A — Truncated treated as terminated in TD target (commit c080d32)

[`tdmpc2.py:325-330`](jax_rl/algos/tdmpc2.py#L325-L330). Our EpisodeWrapper
sets `done=1` at episode timeout (`training.py:121`), so
`batch["dones"] = terminated | truncated`. `compute_td_target` was
reading `terminated = batch["dones"]` and using `(1 - terminated)` to
zero the bootstrap. Source stores `terminated` SEPARATELY from
`truncated` (`common/buffer.py:98-106`) and uses ONLY terminated in
`(1 - terminated) * Q` (`tdmpc2.py:258`). For non-episodic DMC tasks
this means bootstrap is preserved across timeouts. We were zeroing it
on every episode end.

Why Humanoid >> Cheetah:
- Cheetah dense reward (~0.85/step at conv) → losing one bootstrap is
  small bias.
- Humanoid early-training reward tiny (<0.05/step) → bootstrap term
  carries the entire credit-assignment burden → zeroing it kills
  exploration signal. MPPI scores trajectories by biased Q, can't
  discover running.

Fix: `terminated = clip(dones - truncations, 0, 1)`.

### Bug B — Q dropout disabled in policy + qscale paths (commit c080d32)

[`tdmpc2.py:559-567 + 1077-1086`](jax_rl/algos/tdmpc2.py#L559).
Source's `_detach_Qs` (used by `update_pi` via `Q(..., detach=True)`)
is a deepcopy of `_Qs`. `world_model.py:74-80`'s `train()` override
forces ONLY `_target_Qs` to eval mode; `_detach_Qs` rides parent train
mode. Since `self.model.train()` runs before `update_pi`, _detach_Qs
has dropout=0.01 active.

We had `deterministic=True` in both call sites, silently disabling the
regularizer. Earlier fix (1e56a7f) only enabled dropout in the
world-model value-loss path; the policy-loss + qscale paths were
missed.

Fix: `deterministic=False + rngs={"dropout": key}` at both call sites.
Threads new dropout keys (`key_qdrop` in policy_loss,
`key_qscale_drop` in qscale recompute).

### Env parity — action_repeat=2 + episode_length=500 (commit 43b71ad)

Source `dmcontrol.py:54-60` hardcodes `range(2)` action_repeat for ALL
DMC tasks. Each agent action drives 2 control steps; rewards summed.
With ctrl_dt=0.025 → **20Hz agent decisions** (vs our prior 40Hz).
MPPI horizon=3 covers **0.15s** vs **0.075s** if repeat=1 — twice the
temporal extent for planning.

Plumbing:
- Added `action_repeat: int = 2` to `TDMPC2Config` (default for source
  parity).
- Added `action_repeat: int = 1` to `TrainConfig` (back-compat with
  PPO/SAC/TD3).
- `build_train_config_from_tdmpc2` passes through.
- `env_setup.py` passes to `wrap_for_training`.
- All TDMPC2 DMC presets: `episode_length=500` (was 1000). 500 wrapper
  × 2 repeat = 1000 control steps = 25 sec, matching source exactly.
- Discount auto-recomputes to **0.99** (was 0.995) via
  `compute_discount(500, denom=5)`.
