## Bugs Caught (Wrapper Composition)

### Bug 1: JaxReplayBuffer drops extra obs in frame-stack JIT path

When training with `frame_stack=3` + asymmetric critic (`extra_obs_dims={"critic_obs": ...}`), the JIT'd sample function silently dropped critic_obs. KeyError on first gradient step.

**Root cause:** `_make_jit_sample_fs` returned only `batch` while `_make_jit_sample_with_idx` returned `(batch, idx)`. Outer `sample()` called `_gather_extra(batch, idx)` which needs both. Frame-stack path had a comment: *"For now, extra obs with frame-stack is not supported"* — six months later, that comment was load-bearing, not a TODO.

**Fix:** ~10 lines. Made `_make_jit_sample_fs` return `(batch, idx)` and call `_gather_extra` in `sample()`.

### Bug 3 (sort of): GPU OOM with buffer + frame_stack + asymmetric critic

After fixing bugs 1 & 2, third launch crashed with Warp CUDA OOM during graph creation, then a second launch with `XLA_CLIENT_MEM_FRACTION=0.5` crashed with `RESOURCE_EXHAUSTED: 1.95GiB` from JAX itself. Cause: default `buffer_size=4_194_304` plus asymmetric critic (`critic_obs` + `critic_next_obs` extra buffers at 125d each) plus frame stacking allocates ~5 GB of buffer mem alone. Combined with Warp sim + C51 critic activations + XLA scratch, exceeds the RTX 5080's 16 GB. Mitigated by `--buffer-size 2000000`. Added to [lessons/gpu_management.md](.context/lessons/gpu_management.md).

### Bug 2: DomainRandWrapper bypasses intermediate wrappers

When training with `frame_stack=3` + `reset_mode=per_step`, obs_dim came back as 51 instead of 153. Actor params shape (51, 512) vs eval-time obs (153,) → ScopeParamShapeError on first eval.

**Root cause:** `_swap_model` did `env = self.env.unwrapped; ... yield env` — yielded the **unwrapped** base env. So `_reset_with_model` called `v_env.reset()` on `WarpJoystick.reset` directly, bypassing FrameStackWrapper entirely. Same issue would break ActionDelay or any future obs/action wrapper.

**Fix:** Mutate `_mjx_model` on `self.env.unwrapped` (where the field lives), but **yield `self.env`** (the wrapped chain). 6 lines.

### Lesson

Both bugs are the same class: features that worked in isolation break silently when combined. Wrote up [lessons/infrastructure.md](.context/lessons/infrastructure.md) "Wrapper Composition: New Features Are Untested Until Combined" with the recommendation that adding any new wrapper should include integration tests against every other wrapper.

## Resolution: It Was The PD Gains All Along

After dispatching a research agent to verify Kp/Kd values across upstream sim2real Go2 pipelines (unitree_rl_gym, unitree_rl_lab, walk-these-ways, mujoco_playground), confirmed: **every single validated pipeline uses Kd=0.5**. Nobody anywhere uses Kd≥1.0. The Kp=10/Kd=1.0 detour contradicted both external consensus and our own historical lessons (`physics_audit.md` already documented Kd=1.0 as a known failure mode from a stacked-damping bug back in March).

**Reverted to Kp=20/Kd=0.5** and ran three controls to isolate variables:

| Run | Frame stack | linvel | Eval | Online |
|---|---|---|---|---|
| 1: stack=3 + linvel + accel | 3 | ✅ | **285.1** ± 3.2 | 267.4 |
| 2: no stack + linvel + accel | 1 | ✅ | **280.1** ± 3.0 | 265.1 |
| 3: no stack + accel only (deploy obs) | 1 | ❌ | **276.6** ± 3.2 | 252.0 |

**Conclusions:**
- **Kp=20/Kd=0.5 was the sole regression cause.** All three Kp=20 runs converged near or above seed 8001's 276.5 baseline.
- **Frame stacking buys ~2%** (285 vs 280) — confirms `lessons/offpolicy.md` "frame stacking doesn't help locomotion with proprioceptive obs."
- **linvel buys ~1% on eval but ~5% on online return** (280 vs 277, 265 vs 252) — useful for training stability, marginal for converged policy.
- **Deploy-realistic obs (no linvel) hits 276.6** — basically tied with seed 8001's all-time best. Sim2real-ready policy with the same obs space the real Go2 can produce.
