# 2026-04-12 — Off-Policy Loop Extraction

## What happened

Executed the off-policy loop extraction refactor planned on 2026-04-10. The 4 per-algo training scripts (`train_sac.py`, `train_td3.py`, `train_fast_sac.py`, `train_fast_td3.py`) now delegate to a shared `jax_rl/training/offpolicy_loop.py::run_offpolicy_loop` helper. Each script dropped from ~300 lines to ~115-130 total (~30-43 line `train()` bodies). FlashSAC stays standalone.

### Approach: shared function, not base class

The review (2026-04-10) initially recommended re-unifying the 4 scripts back into one `train_offpolicy.py`. Steven rejected this — the problem was signal-to-noise, not duplication. The fix was extracting the loop into a function that each thin per-script calls, keeping algo-specific decisions (optimizer, explore closure, log fields) visible at the top level.

### Key design decisions

- **`make_env_bundle` wraps `make_envs`** instead of changing `make_envs` signature — avoided churning 11 existing callers
- **Non-breaking ObsPipeline merge** — added `critic_obs_dim` to `make_buffer` first, deleted old `make_buffer_with_critic` after all callers migrated (no broken intermediate commits)
- **Removed `_ts = training_state` cargo cult** — the lambda is called synchronously, so the Python closure capture concern was wrong. Replaced with a comment explaining why.
- **CPU stub-env test as commit gate** — runs in <12s, no GPU, catches glue bugs. Deferred real-env tests to GPU availability.

## Lessons

- **Extract loops, not classes** — when 4 scripts share 85% of code, the instinct is Trainer base class or re-unification. Both add noise. A shared helper function keeps each script readable while eliminating the duplication. The variation points (algo, optimizer, explore closure, log fields) are the function parameters, not virtual methods or config branches.
- **Non-breaking adds before breaking deletes** — extending a method's signature (add `critic_obs_dim` param with default `None`) then migrating callers then deleting the old method avoids broken intermediate commits. Two commits instead of one, but zero breakage window.
- **`pytest.mark.slow` requires registration** — unregistered markers don't skip tests, they just warn. Without `pyproject.toml` registration, "deferred" GPU tests run anyway and OOM on a busy GPU.
