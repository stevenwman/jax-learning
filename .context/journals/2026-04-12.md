# 2026-04-12 — Off-Policy Loop Extraction

## What happened

Executed the off-policy loop extraction refactor planned on 2026-04-10. The 4 per-algo training scripts (`train_sac.py`, `train_td3.py`, `train_fast_sac.py`, `train_fast_td3.py`) now delegate to a shared `jax_rl/training/offpolicy_loop.py::run_offpolicy_loop` helper. Each script dropped from ~300 lines to ~115-130 total (~30-43 line `train()` bodies). FlashSAC stays standalone.

### Approach: shared function, not base class

The review (2026-04-10) initially recommended re-unifying the 4 scripts back into one `train_offpolicy.py`. Steven rejected this — the problem was signal-to-noise, not duplication. The fix was extracting the loop into a function that each thin per-script calls, keeping algo-specific decisions (optimizer, explore closure, log fields) visible at the top level.

### Key design decisions

- **`make_env_bundle` wraps `make_envs`** instead of changing `make_envs` signature — avoided churning 11 existing callers
- **Non-breaking ObsPipeline merge** — added `critic_obs_dim` to `make_buffer` first, deleted old `make_buffer_with_critic` after all callers migrated (no broken intermediate commits)
- **Removed `_ts = training_state` cargo cult** — the lambda is called synchronously, so the Python closure capture concern was wrong. Replaced with a comment explaining why.
- **CPU stub-env test as commit gate** — runs in <12s, no GPU, catches glue bugs. Deferred real-env tests to GPU availability.

## Lessons

- **Extract loops, not classes** — when 4 scripts share 85% of code, the instinct is Trainer base class or re-unification. Both add noise. A shared helper function keeps each script readable while eliminating the duplication. The variation points (algo, optimizer, explore closure, log fields) are the function parameters, not virtual methods or config branches.
- **Non-breaking adds before breaking deletes** — extending a method's signature (add `critic_obs_dim` param with default `None`) then migrating callers then deleting the old method avoids broken intermediate commits. Two commits instead of one, but zero breakage window.
- **`pytest.mark.slow` requires registration** — unregistered markers don't skip tests, they just warn. Without `pyproject.toml` registration, "deferred" GPU tests run anyway and OOM on a busy GPU.

## Part 3 — Second 4-Persona Review + Truncation Bug Fix

After the first review round landed, dispatched a second 4-persona review to see what was still stale. New findings plus one big code bug.

### The truncation bug (critical)

PhD reviewer cross-referenced SAC/TD3 against Fast*/Flash* truncation handling and found they disagreed. Investigation confirmed:

- `EpisodeWrapper` sets `done = terminated OR truncated`, `truncation = truncated AND NOT terminated`
- SAC/TD3 (correct): `target = r + γ(1-done)V_next`, loss mask `(1-truncation)` — zeros bootstrap on both, drops pure-timeout rows from loss
- Fast*/Flash* (buggy): `effective_done = max(done, truncation)` (no-op — `done` already includes timeouts), no loss mask — pure-timeout rows contributed an `r`-only target, teaching `Q = r` at timeout steps

On long-horizon tasks (Go2, Humanoid) this caused systematic Q underestimation proportional to `timeout_rate × true_tail_value`. The FlashSAC docstring even said "terminated only" but the code passed `batch["done"]` which is term-OR-truncated — docstring was lying.

Fixed in commit `82c9fe5`. 3 algos now use the Brax convention (`target with done`, `loss with mask = 1-truncation`). 25 unit tests still pass. Actual training behavior on Go2/Humanoid should improve, especially the ceiling. Benchmarks from before this commit are not directly comparable.

Also discovered `handle_truncation` constructor arg on all 5 off-policy algos was dead code — stored on `self`, never read. The real switch is `cfg.handle_truncation` in the training loop (controls whether `truncation` gets populated in the buffer). Removed in commit `39c7ddc`.

### Lessons from round 2

- **Ghost refs recurrence.** The 18k sps claim was the same pattern as the obs-dims bug: a number measured on one env (CheetahRun), cited generically on another (Go2). Not as egregious as the obs dims because the number was real, just mislabeled. But same failure mode — a later writer trusted the earlier writer who trusted a half-remembered measurement.
- **PhD cross-ref caught the truncation bug that 3 other reviewers missed.** High schooler couldn't read algo code. Frontend doesn't read algo code. Undergrad verified API surface matched code but didn't diff the algo internals against each other. Only the PhD reviewer systematically compared the 6 algos against each other and noticed the divergence. Reviewer diversity is the point.
- **Docstring audits.** FlashSAC's docstring said `done: terminated only` while `batch["done"]` was term-OR-truncated. Docstrings can lie silently for years. Worth periodic audits against actual wrapper semantics.
- **Validation blocks catch cross-agent drift.** Added `validation: links: unrecognized_links: warn` to mkdocs.yml; immediately caught a broken link between two parallel subagents (one created a link to a file the other was still writing). Would have shipped broken otherwise.

### Lessons from rounds 3+4

- **"Cleanup of round N introduces ghost refs for round N+1" is systemic, not incidental.** Every round catches the prior round's artifacts. The drift test suite is the right response — mechanizes the pattern checks so human reviewers can focus on semantic issues.
- **The drift test caught 16 issues on first run.** That's the ROI justification. Any time a writer deletes a constructor param, the docs will surface it on next commit — no more "we fixed the code, forgot the docs."
- **The test can't catch everything.** Things it DOESN'T catch: FAQ claims that are factually wrong (PPO Go2 timing), algorithmic descriptions that omit features (policy_delay), pages that should reference something but don't (DomainRandWrapper absent from wrappers.md). These still need humans.
- **False positives are fine** if the check is cheap. The undergrad reviewer flagging real arXiv IDs as fake cost ~5 min of WebFetch to verify. Better than missing a real hallucination.
- **Root-cause fixes beat patch fixes.** The phantom CLI flags came from the generator script, not a hand-edit — fixing the generator fixed it everywhere at once.
