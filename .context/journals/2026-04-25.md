# 2026-04-25 (afternoon) — TD-MPC2 J3 CheetahRun debug → paper-match

**TL;DR.** J3 smoke (CheetahRun, 100k env steps) showed MPPI eval climbing
to ~17 then collapsing to ~6 by step 50k. Audit found 3 correctness bugs;
applying them cleared the regression. J3 1M then matched paper target:
**best mppi=837.51 ± 1.35 (40 episodes) at step 500k, paper ≈850**. Late-step
collapse pattern (-40-45% in last 10% of training) recurs in both v4
(100k) and v5 (1M) — flagged for separate investigation. Also shipped
runtime extraction, eval-only ckpt scoring script, eval-key isolation,
and a determinism lesson (mujoco_warp non-det documented + tracked).

## Bugs found and fixed (commit 1e56a7f)

1. **MPPI temperature inverted** ([tdmpc2.py:693](jax_rl/algos/tdmpc2.py#L693))
   — source uses `exp(temperature * Δ)`, ours used `exp(Δ / temperature)`.
   With `cfg.mppi_temperature=0.5` ours was 4× sharper softmax over elites
   (coef 2.0 vs 0.5). Concentrated weight on top elite — amplifies any
   Q-overestimation peak.

2. **Q dropout disabled in world-model value loss**
   ([tdmpc2.py:417](jax_rl/algos/tdmpc2.py#L417)) — source `_Qs` is in
   train mode during `_update` → `dropout=0.01` active in the value-loss
   Q forward. We had `deterministic=True` everywhere → the regularizer
   that helps prevent Q overestimation was disabled. Fix splits a
   per-step dropout key inside the world-model loss scan.

3. **Replay buffer cross-env contamination**
   ([jax_replay_buffer.py:375](jax_rl/buffers/jax_replay_buffer.py#L375))
   — `add_batch` writes a `(num_envs,)` batch into consecutive indices,
   so env `e`'s transitions live at indices `ptr+e, ptr+e+num_envs, ...`.
   Old `sample_sequence` used offsets `[0, 1, 2, 3]` — returned a
   "trajectory" stitched from 4 different envs. Episode-id check passed
   because all envs reset on truncation simultaneously (sync ep counters).
   Fix: added `stride` parameter (default 1 = source-compatible
   single-env), wired `stride=num_envs` in train script.

**Bug 3 was the kingpin.** Before fix: world model trained on impossible
cross-env transitions. Trajectory shape was climb-then-collapse:
- v2 (no fixes): peak 15.65 (10k) → 6.76 (50k) collapse
- v3 (bugs 1+2 only): peak 17.00 (30k) → 8.08 (80k) collapse
- v4 (all 3 fixes): peak 523.36 (90k), validated at std=1.49 over 40
  episodes via new `scripts/eval_tdmpc2.py`

## Eval-key isolation (commit b5a8c70)

Pre-fix the eval branch did `key, eval_key = split(key)`, consuming the
training PRNG. Side effect: eval cadence (`cfg.eval_every`) silently
affected the training trajectory. Caught when v5 (eval_every=50k) at step
50k showed mppi=392 vs v4 (eval_every=10k) showing 307 — same seed,
different cadence → different post-eval PRNG → different sampled batches.

Fix: derive `eval_key` from `eval_base_key = PRNGKey(seed+9000)` folded
with `eval_index = (step_counter-1) // cfg.eval_every`. Training key
untouched in the eval branch.

Verified within-process: instrumented eval branch with `key_before` /
`key_after` prints, ran 12k smoke with 4 evals — all 4 reported
`match=True`. Cross-process bit-identicality is impossible on GPU due
to mujoco_warp non-determinism (see lesson below).

## Determinism diagnostics (commit 391e718)

`scripts/check_tdmpc2_determinism.py` — 3 subchecks (`init` / `update` /
`env`), each <30s. Empirical findings (run twice in separate processes,
diff hashes):

| check | XLA flag off | XLA flag on |
|---|---|---|
| init | bit-ID | bit-ID |
| update (50 steps fake batch) | DIVERGES | bit-ID |
| env (50 steps from reset, fixed actions) | DIVERGES | DIVERGES |

`env` diverges at the very first `reset` — JAX-side state matches but
raw obs from MuJoCo Warp differ across processes. Confirms divergence
is in Warp, not in our jax wrapper.

Researched online (mujoco docs FAQ + mujoco_warp#562 + NVIDIA/warp#1355):
non-determinism is officially acknowledged, root cause is `wp.atomic_add`
in narrowphase contact resolution, only `wp.set_device("cpu")` is a
workaround today, fix in flight (Warp 1.14, target ~Jun 2026).

Lesson written: `.context/lessons/determinism.md`. Indexed in
`LESSONS.md`. Implication for any future repeatability discussion:
report seed-averaged results, not single-run; same-process re-runs
appear deterministic but cross-process won't be.

Both v4 (100k) and v5 (1M) show the same pattern: MPPI eval drops 40-45%
over the last 10k env steps. Same shape at different scales, so likely
systematic, not noise. Hypotheses for next session:

- Q overestimation accumulating that the regularizers (dropout +
