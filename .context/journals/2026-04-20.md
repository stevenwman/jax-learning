## The `reset_mode` footgun (fix #5)

Pilot v1 (5M steps, no `--reset-mode per_step` flag) ran for 3h and produced `mean_level=0` everywhere. Type distribution was `rough=4, pyramid_up=11, pyramid_down=7, tilted=10` (totaling 32 but not 8 each). Indicates terrain_type was being randomized per-episode by the **inner** env's reset, with no wrapper overriding it back.

Root cause: `TerrainCurriculumDRWrapper` is only applied in `env_setup.make_envs` when `cfg.reset_mode == "per_step"`. `TrainConfig.reset_mode` defaults to `"legacy"`. My launch command didn't pass `--reset-mode per_step`, and the curriculum preset didn't set it. Training ran with plain AutoResetWrapper, no curriculum logic.

Surprising that the training didn't crash — the env functions fine, reward/obs still valid, episodes still complete. It just has no curriculum. Added `reset_mode="per_step"` to all curriculum presets (PRESETS, FAST_SAC, FLASH_SAC) so future launches can't forget.

Symptom to watch: if distribution deviates from `num_envs / num_cols` per type, wrapper isn't running.

## Throughput + comparison to published pipelines

v5: 341 sps total across 32 envs = ~10.6 sps/env. 

Bottleneck is **VRAM**, not FLOPs: 16GB RTX 5080 caps us at 32 envs (curriculum env has ~1500 geoms vs ~100 on flat). 32 envs poorly amortize Warp kernel dispatch overhead.

- MJLab (same MuJoCo Warp backend), Go2 flat PPO, 1024 envs → ~15 sps/env total ~15k sps
- RSL-RL (Isaac Gym), anymal_c, 4096 envs, PPO → ~20-50 sps/env
- MuJoCo Playground (Brax), Go2 flat PPO, 4096 envs → ~15-25 sps/env

Per-env throughput is on par. Total wall-clock is 30-50× slower because we're memory-limited to 1% of their parallelism. SAC (UTD=8) also halves throughput vs PPO. Not a GPU speed problem, a GPU memory problem.

## Termination debugging (fix #4)

Original `_get_termination` inherited from parent: `flipped | base_z < 0.18` (world frame).

- **pyramid_down L5:** robot standing at pit bottom has `base_z ≈ -0.7m`. Auto-terminates on every episode regardless of policy → `mean_level` clamped at 0 for pyramid_down.
- **elevated terrain (pyramid_up ring_height > 0.2m):** robot standing on ring has `base_z > 0.5`, doesn't fire even when torso actually collapses but stays in absolute frame.

Fix: `flipped | base_contact > 0` using `<contact body1="base_link" reduce="mindist" num="1" data="found"/>` sensor added to scene template. Probe script confirmed sensor fires on both CPU MuJoCo and Warp backends: 0 when upright, 4 (num contact points) when torso flat on floor.

Deliberate exclusion: robot lying on side with legs propped has `base_contact=0, upvector_z~0.8`. Not terminated — leg contact is fine, policy may still recover. Flipped check catches full inversions.

Added two regression tests (`test_flipped_robot_triggers_termination`, `test_standing_in_bowl_does_not_terminate`).

## The unified redesign (fix #7)

Dual-class had practical issues:
- Class A random Bernoulli cmd sends robot out of tile in ~10s. Robot spends half the episode on neighbor's physics.
- Class A promote criterion went through two rewrites (max_dist → tracking-error), both ad-hoc thresholds.

User's insight: **if all types use goal-directed holonomic cmd + random yaw, the rotating body frame naturally produces omnidirectional linvel DR**. As yaw spins, the fixed world-frame goal direction sweeps through every body-frame angle. Richer than discrete Bernoulli step-jumps.

Unification:
- All 4 types: spawn rim, goal at tile center, holonomic body-frame cmd
- Single promote rule
- Single demote rule
- Drop Class-A-specific state fields (`episode_max_dist_from_spawn`, `episode_tracking_error_sum`, `episode_step_count`)
- Drop `_IS_GOAL_DIRECTED` gating everywhere

v5 confirms this works: 4× faster advancement than v3 at same step count.

## Zero linvel after reach (fix #8)

Once robot enters 0.5m goal zone, `episode_reached_goal` latches True. Flip cmd_vx/cmd_vy to zero. Robot stands and tracks random yaw (from parent's sampler) for the rest of the episode.

Benefits:
1. Full 20s episode used for data
2. Explicit "stop at target" behavior
3. Yaw controller exercised at zero linvel (common deployment requirement)
4. Eliminates dist≈0 numerical degeneracy in goal-direction normalization

Implementation: read `episode_reached_goal` **inside** the `_override` closure. When called post-super().step(), the closure sees the freshly-flipped value.
