# 2026-03-22 — Infrastructure Cleanup + Q Diagnostics

## What we did

### FastDSAC Inf root cause found
Stress tested FastDSAC with edge case injection instead of waiting for full training runs. Found that MJX produces `Inf` (velocity overflow), not just `NaN` (solver failure). Our guard only checked `isnan()`. Single `Inf` obs → `Inf * 0 = NaN` in network → total param corruption.

Fix: `jnp.isinf()` added to env step guard alongside `jnp.isnan()`.

FastDSAC 1024 envs with both fixes (Inf guard + 400K buffer) running overnight.

### TrainConfig cleanup
Moved PPO-specific fields (`num_steps`, `policy_hidden_dim`, `value_hidden_dim`, `anneal_lr`, `max_grad_norm`, `squash`, `state_dependent_std`, `activation`) from TrainConfig into PPOConfig. TrainConfig now has only shared fields. Off-policy presets no longer need `ppo=None` or `anneal_lr=False`.

Code done, needs GPU test before commit (GPU occupied by FastDSAC).

### Q prediction diagnostics
Added optional `q_fn` argument to eval runner. When provided, computes:
- Q bias (mean(Q_pred - MC_return))
- Q RMSE
- Q-MC correlation
- Q mean vs MC mean

Backward compatible — existing train scripts work unchanged. To enable, pass a 3-line Q function closure at eval time. Needs GPU test.
