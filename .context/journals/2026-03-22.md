# 2026-03-22 — Infrastructure Cleanup + Q Diagnostics

## What we did

### FastDSAC Inf root cause found
Stress tested FastDSAC with edge case injection instead of waiting for full training runs. Found that MJX produces `Inf` (velocity overflow), not just `NaN` (solver failure). Our guard only checked `isnan()`. Single `Inf` obs → `Inf * 0 = NaN` in network → total param corruption.

Fix: `jnp.isinf()` added to env step guard alongside `jnp.isnan()`.

FastDSAC 1024 envs with both fixes (Inf guard + 400K buffer) running overnight.

### lax.scan benchmark — no speedup
Benchmarked scanned gradient loop vs Python for-loop at HumanoidRun scale (67-dim, 8K batch, 50 updates). Result: 1.03x — essentially identical. The gradient computation (~64ms/update) dominates dispatch overhead (~0.1ms). Not worth implementing.

### MJX recompilation — root cause identified
Systematic isolation:
- Env only: 2 while compiles (startup)
- Env + algo: 2 (algo doesn't cause recompilation)
- **Env + eval: 12 from 5 evals** (each eval adds ~2 while + 2 scan)
- Tried casting weak_type `.time` field after `env.reset()` — removed at pytree level but recompilation persisted
- **Cause is internal to MJX's step function**, not the input pytree. Upstream issue.
- Mitigation: `XLA_CLIENT_MEM_FRACTION=0.7` (~5% overhead)

### Builders unification — DONE
All off-policy algos (SAC, TD3, FastTD3, FastSAC) now use composed Actor/DeterministicActor modules from `builders.py` instead of inline MlpEncoder + Head construction. PPO's Critic renamed to VCritic.

What changed per algo:
- SAC/FastSAC: `Actor(enc_cfg, pol_cfg)` replaces `MlpEncoder(enc_cfg) + GaussianHead(pol_cfg)`
- TD3/FastTD3: `DeterministicActor(enc_cfg, action_dim)` replaces `MlpEncoder(enc_cfg) + DeterministicHead(action_dim)`
- `_actor_forward` closures simplified from 3 lines (unpack params, encode, head) to 1 line (`actor.apply(params, obs)`)
- `init()` simplified from separate encoder + head init to single `actor.init(key, obs)`
- Q networks unchanged (QHead/DistributionalQHead are standalone)

**What this enables:** Adding a CNN encoder means changing `builders.py` to use `CnnEncoder` instead of `MlpEncoder`. Zero algo file changes.
