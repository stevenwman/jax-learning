# 2026-04-26 — Env-backend refactor: gym envs train through `train_sac` now

**TL;DR.** Refactored the env-construction layer so non-MJX envs (gym, isaaclab planned) plug into the same `run_offpolicy_loop` / `evaluate_*` / `record_video` plumbing as Playground/Warp envs. `EnvBundle` is now a Protocol with a `backend_kind` discriminator and a registry under `jax_rl/training/env_backends/`. Adding a new env backend is one file. `train_sac --env HalfCheetah` runs end-to-end on `gymnasium[mujoco]` with eval=5697 ± 43 at 200k steps (above published SAC baselines for that step count). 6 commits on a worktree branch `env-backend-refactor`; IsaacLab branch deferred (no install/test target yet).

This is the start-of-day refactor; the late-day TD-MPC2 / curriculum / FlashSAC work is on the linen branch (separate session, separate journal).

---

## Why

Two pain points:

1. **`scripts/train_pusht.py` was a 476-line fork of the SAC stack** — its own numpy replay buffer, its own normalization wrapper, its own training loop, its own eval. Adding any non-Playground env (PushT, MetaWorld, eventually IsaacLab) meant copying the whole stack. The off-policy loop in `run_offpolicy_loop` was already env-agnostic Python iteration, but `make_envs(cfg, seed)` hardcoded `pg_registry.load()` so non-MJX envs couldn't reach it.

2. **Labmate portability.** Goal is for someone running IsaacLab to pull this repo and slot their env in without forking. Without a backend abstraction, every new env becomes another `train_<env>.py`.

### Phase 0 — `EnvBundle` Protocol (commit 9273c2b)

Relocated the `EnvBundle` dataclass from `env_setup.py` to its own module `jax_rl/training/env_bundle.py`. Added three fields: `backend_kind: Literal["mjx", "gym", "isaaclab"]`, `num_envs: int`, `render_fn: Optional[Callable]`. MJX path defaults to `backend_kind="mjx"`, no behavior change.

This is pure scaffolding — no new envs, no new behavior. Sets up the dispatch surface for Phases 1-5.

### Phase 1 — Backend registry (commit 2c3f68a)

`jax_rl/training/env_backends/__init__.py` introduces `BACKEND_BUILDERS`, `register_backend(name, builder)`, `detect_backend(env_name)`, `build_env_bundle(cfg, seed)`. Detection rule: `IsaacLab/<...>` → isaaclab, registered gym names → gym, else → mjx.

`mjx_backend.py` houses the relocated MJX code: custom env registration with Playground, the NaN-safe step wrapper (`_make_nan_safe_step`), `make_envs`, `make_mjx_env_bundle`. Self-registers as `"mjx"` at import. `env_setup.py` becomes a thin shim: `make_env_bundle()` dispatches via the registry; `make_envs` and `_make_nan_safe_step` are re-exported for legacy callers (train_ppo*, train_flashsac, test_algo_configs).

### Phase 2 — Gym backend (commit f4ac6ad)

`gym_backend.py`:
- `GymState` dataclass mirroring MJX state surface (`.obs / .reward / .done / .info["truncation"]`) so the off-policy loop works unchanged.
- `make_gym_env_bundle`: builds `gym.vector.{Sync,Async}VectorEnv`, caps `num_envs` at `os.cpu_count()` with a warning.
- `GYM_ENV_FACTORIES` registry; PushT first concrete entry — reads env_kwargs from cfg (obs_type, block_shape, reward_mode, etc.), ports `NormalizeObsWrapper` + `ActionRepeatWrapper` from `train_pusht.py`, adds `gym.wrappers.RescaleAction` for [-1,1] policy → gym action space.
- Self-registers as `"gym"` on import.

Gym needs a Python-loop eval (no `lax.scan`):
- `jax_rl/utils/eval.py`: add `evaluate_gym()` — single-env serial Python loop, same return shape as `evaluate()`. Skips Q-bias diagnostics (gym mostly used for low-dim research; backfill if needed).
- `jax_rl/training/eval_runner.py`: dispatches `evaluate` vs `evaluate_gym` via `TrainContext.backend_kind`.
- `TrainContext` gets a `backend_kind` field (default `"mjx"`); `offpolicy_loop` threads `bundle.backend_kind` into ctx.

`TrainConfig`: add `env_kwargs: dict` field for backend-specific construction details (gym/isaaclab); ignored by mjx.

Smoke: `train_sac --env PushT --total-timesteps 3000` ran warmup → eval → ckpt cleanly.

### Phase 4 — PPO routing (commit 8d23ca3)

`train_ppo.py` (the existing Python-loop variant for non-JIT envs like MJWarp) now uses `make_env_bundle()`. Works for any registered backend.

`train_ppo_fast.py` (the lax.scan/MJX fast path) routes through `make_env_bundle()` but raises a clear `ValueError` if `backend_kind != "mjx"`, since lax.scan requires JAX-traceable env_step. Error message points at `train_ppo.py` for non-MJX backends.

Validated `train_ppo --env CartpoleBalance --num-envs 64 --total-timesteps 5000` → eval 309 (matches prior MJX path; bundle round-trip clean). `train_ppo_fast --env PushT` raises with the expected guard message.

### Phase 5 — `record_video` dispatch (commit ccc851f)

`record()` early-dispatches by `detect_backend(env_name)`:
- `"gym"` → `_record_gym()`: single-env Python loop, render each step via `env.render(mode='rgb_array')`, save mp4 + npz with obs/actions/rewards. Reads `env_kwargs` from `meta.json` to rebuild the env via `GYM_ENV_FACTORIES`. PushT supported today.
- `"mjx"` / default → existing path unchanged (Playground env, lax.scan rollout, mujoco.Renderer for frames, qpos/qvel traj).

Smoke: recorded a 50-step PushT rollout from a 3k-step SAC ckpt — coverage 0.345, mp4+npz saved.

### Bonus — gymnasium[mujoco] benchmark factories (commit 07e7707)

Wired the standard SAC/PPO benchmark envs through gym_backend: `HalfCheetah-v5`, `Hopper-v5`, `Walker2d-v5`, `Humanoid-v5`, `Ant-v5`, `Pendulum-v1`, `LunarLanderContinuous-v3`. These envs already expose continuous action_space in `[-1, 1]` and 1D state obs — no extra wrappers needed; just forward env_kwargs to `gym.make()`.

## End-to-end validation

Ran `train_sac --env HalfCheetah --total-timesteps 200000 --num-envs 8 --seed 0` on `gymnasium[mujoco]` HalfCheetah-v5 — an env this codebase had never seen before this refactor.

| step | online return | eval | Q1 | alpha |
|---|---|---|---|---|
| 30k | 47.9 | — | 55 | 0.07 |
| 32 eps | — | **2776 ± 151** | — | — |
| 60k | 1720 | — | 200 | 0.21 |
| 160k | 4180 | **5261 ± 49** | 327 | 0.27 |
| 192 eps | — | **5659 ± 64** | — | — |
| 200k final | 4490 | **5697 ± 43** | 348 | 0.27 |

Tight std (~1% of mean) at convergence. Above published SAC baselines at this step count (3-5k typical). The fast convergence is from `grad_updates_per_step=8` (high-UTD SAC default in `sac_config.py`) — 200k env steps × 8 = 1.6M effective gradient updates ≈ 240k vanilla-SAC equivalent steps. SAC published curves hit ~3000-5000 at the equivalent of 200-300k vanilla steps. Tracks.

The point is: zero code outside `gym_backend.py:_make_gymnasium_mujoco_factory` was needed. Single entrypoint, registered factory, train.

## What changed in the codebase shape

```
jax_rl/training/
├── env_bundle.py           ← Protocol/dataclass, single source of truth
├── env_setup.py            ← thin shim: dispatch + legacy re-exports
├── env_backends/
│   ├── __init__.py         ← registry, detect_backend, build_env_bundle
│   ├── mjx_backend.py      ← Playground + Go2 + NaN-safe step (relocated)
│   └── gym_backend.py      ← AsyncVecEnv + GymState + 8 env factories
├── eval_runner.py          ← dispatches by ctx.backend_kind
└── offpolicy_loop.py       ← unchanged, threads backend_kind into ctx
```

The training infrastructure is now structurally separated from the env runtime. That separation is the actual deliverable.

## Trade-offs & deferred work

**`scripts/train_pusht.py` still exists.** Phase 6 deletes it once `train_sac --env PushT` reproduces 89% sto cov at 2M steps — that's a validation run, not a code change. Doing the deletion before validation is a foot-gun: the old script is the reference numbers we'd compare against.

**PPO on gym requires `train_ppo.py` (Python-loop variant).** `train_ppo_fast.py` is JIT/scan, can't take numpy step. The split was already there — we just made it explicit + guarded with a clear error pointing at the right script.

**IsaacLab is plan-only.** No install, no test, no smoke. The Protocol is in place; building the backend module is one file when the time comes.

**Gym eval skips Q-bias diagnostics.** `evaluate_gym` returns `eval_mean/std/min/max` only. Q-bias requires a vmapped MC return computation that doesn't translate to single-env Python loop without rewriting; low-dim gym research envs don't typically need it. Backfill if a use case shows up.

**`train_ppo_contraction.py` and `train_flashsac.py` keep using legacy `make_envs`.** These are MJX-specific PPO/SAC variants that don't need the dispatcher. They'd need their own bundle migration if anyone ever runs them on gym. Cheapest path is to migrate them when there's a real reason.

## Why a worktree?

Active development on linen during this session (TD-MPC2 J3/J4 paper-match, polyak refactor, etc.) was touching `env_setup.py`, `train_*.py`, `__init__.py` exports — exactly the files the refactor rewrites. Doing the refactor on linen would have created rebase pain on every TDMPC2 commit. Worktree at `../jax-learning-envrefactor/` isolated the work; merge happens at the end.

Trade-off: each phase will rebase against linen's evolving state when we merge back. Expected — and cheaper than continuous rebase mid-refactor.
