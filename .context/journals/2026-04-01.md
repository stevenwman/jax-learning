## Frame stacking

**Decision:** Build as universal wrapper, not per-env inline code.

Two agents debated priority ordering in `chat.md`:
- Consensus: frame stacking (quick win) -> action delay (sim2real) -> asymmetric off-policy critic (novel contribution)
- Key insight: make sim match reality first, then improve training on realistic sim

**Implementation:**
- `FrameStackWrapper` (`jax_rl/envs/wrappers/frame_stack.py`) — subclasses Playground's `Wrapper`, works with dict and flat obs
- Applied in `env_setup.py` when `cfg.n_frame_stack > 1`, BEFORE `wrap_for_brax_training`
- `TrainConfig.n_frame_stack` (default 1), `--frame-stack` CLI flag on all 3 training scripts
- Deploy `ObsBuilder` mirrors with numpy frame stack buffer
- `sim2sim_direct.py` infers n_frame_stack from checkpoint obs_dim

**Known limitation:** Brax auto-reset replays cached initial state, doesn't re-call reset(). Frame stack goes stale for N-1 steps at episode boundaries. For 3 frames / 1000-step episodes = 0.2% of steps. Documented in wrapper docstring.

## Sample-time frame stack reconstruction

Built efficient replay buffer for frame stacking — stores raw 48d obs, reconstructs 144d stacks at sample time. 83% memory reduction (5.08 GB → 0.77 GB). Also eliminates `next_obs` storage (derived from `buffer[i + num_envs]`). 145/145 tests pass.

## Frame stacking A/B results

FastSAC on Go2WarpJoystickFlat, 1024 envs, 20M steps:
- **Baseline (seed 6001):** eval 276.5 @ 17M steps
- **3-frame stack (seed 8001):** eval 271.3 ± 8.3 @ 20M steps
- **3-frame stack (seed 8000):** eval 274.6 ± 6.0 @ 20M steps

**No measurable difference.** `last_action` in obs already provides temporal context. Frame stacking is for vision RL, not proprioceptive locomotion. Infrastructure (wrapper, buffer, CLI) retained for future use.
