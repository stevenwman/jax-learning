# 2026-03-24 — PPO Performance Investigation & Fast Training

## What we did

### Brax PPO A/B test — confirmed env is fine
Ran Brax's own PPO on both Go1 and Go2 at 512 envs, 50M steps:
- **Go1 Brax PPO:** eval 21.7 — matches the published Playground paper curve (~25 at 100M)
- **Go2 Brax PPO:** eval 17.9 — similar trajectory, slightly lower (different robot physics)
- **Our PPO Go2:** eval 9.0 — 2x worse sample efficiency

Conclusion: env produces correct rewards, our PPO implementation had real differences.

### Contact physics fix
Discovered Menagerie's Go2 MJCF has marshmallow-soft foot contacts (solimp=0.015) vs Playground's Go1 firm contacts (solimp=0.9). Fixed in `go2_base.py` by overriding foot geom properties after model loading.

### Wall-clock profiling — found 87x overhead
Python collect loop (per-step select_action + buffer.add + norm) forces GPU pipeline sync:
```
Pure env.step (512 envs, 20 steps): 0.111s → 92,000 sps
Python collect loop:                9.729s → 1,053 sps
```

### Built train_ppo_fast.py — lax.scan collect
Replaced Python collect loop with `jax.lax.scan`. Result: **55k sps** (up from 32k). Remaining gap to Brax's 82k is the update phase.

### Code-diffed Brax PPO vs ours — found 2 real differences
Instead of running more training, just read the code:

1. **Value loss scaling:** Brax `0.5 * 0.5 = 0.25x`, ours `1.0x` → 4x larger critic gradients
2. **Advantage normalization:** Brax full-batch, ours per-minibatch → higher variance

Fixed both in `ppo.py`. Running seed 600 to validate — early results show gap narrowing from 2x to ~1.3x.

Full trail in `.context/go2_ppo_debugging.md` with 8 hypotheses tested, run log, and key lessons.
