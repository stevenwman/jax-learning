### FastSAC — C51 + SAC underperforms FastTD3 (known issue)

**Run 1 — wrong config (256, 256 hidden, SAC preset):**
Plateaued at **335** eval by 20M steps, flat through 67M. OOM'd on eval at 67M (CUDA graph limit). Used vanilla SAC preset with (256, 256) hidden — half the capacity of FastTD3's (512, 512).

**Run 2 — correct config (512, 512 hidden, proper FastSAC preset):**
Created `get_fast_sac_preset()` matching FastTD3 scale. Improved to **~375** eval by 26M steps but still plateauing. Alpha dropped to near-zero quickly — SAC degenerating into poor deterministic policy.

**Root cause (confirmed by literature):**
The FastDSAC paper (arXiv:2603.12612, March 2026) introduces FastSAC as a **baseline** and documents exactly this failure mode:
1. **Alpha/entropy collapse** — target entropy heuristic too aggressive at scale, alpha → 0, SAC loses its exploration advantage
2. **C51 quantization + entropy interaction** — entropy bonus shifts reward distribution, fixed atoms can't track it
3. **Uniform entropy waste** — diagonal Gaussian spreads exploration uniformly across all action dims instead of focusing on task-relevant ones

**The naming clarification:**
- **FastTD3** = TD3 + C51 + large batch (Seo et al. 2025) — what we have
- **FastSAC** = SAC + FastTD3 recipe (baseline in FastDSAC paper) — what we built, known to underperform
- **FastDSAC** = FastSAC + continuous Gaussian distributional critic + dimension-wise entropy modulation (the actual fix) — what we need to implement

### FastDSAC implementation — Gaussian distributional critic + DEM

Implemented FastDSAC from arXiv:2603.12612. Three key changes from FastSAC:

1. **Gaussian distributional critic** (`GaussianQHead`) — outputs (mean, variance) via softplus instead of C51's 51-atom logits. Loss is Gaussian NLL with decomposed mean/variance gradients, scaled by ω (batch mean variance).

2. **Dimension-wise Entropy Modulation (DEM)** — actor gets a third output head (`dem_logits`). Temperature-scaled softmax produces per-dim weights that modulate std: `σ_i = w_i * exp(log_std_i)`. Budget constraint: weights sum to action_dim. No separate DEM loss — learns through actor gradient.

3. **Target entropy = 0** (not -dim(A)) — prevents alpha collapse that killed FastSAC. Alpha decays slowly (0.99 → 0.65 in first 150k steps) instead of collapsing to 0.005.

**New files:**
- `jax_rl/algos/fast_dsac.py` — algorithm with Gaussian critic loss + DEM actor
- `jax_rl/networks/heads/q_gaussian.py` — GaussianQHead (mean + softplus variance)
- `jax_rl/configs/fast_dsac_config.py` — FastDSACConfig (DEM τ, β range, AdamW settings)
- `train_fast_dsac.py` — training script

**Modified files:**
- `jax_rl/networks/heads/gaussian.py` — added optional dem_logits output
- `jax_rl/configs/networks_config.py` — added `dem` flag to PolicyHeadConfig
- `jax_rl/configs/env_presets.py` — added `get_fast_dsac_preset()`

**Bug during bringup:** AdamW requires `params` argument in `optimizer.update()` for weight decay. FastSAC/TD3 used plain Adam which doesn't need this. Fixed by passing `params=q_params` and `params=state.actor_params` to the update calls.

**Early training signals (CheetahRun, first 150k steps):**
- Q1 climbing steadily (5 → 30), Gaussian critic learning
- Q1 variance decreasing (0.43 → 0.05), critic getting confident
- Alpha at 0.65 (NOT collapsed like FastSAC's 0.005)
- Entropy stable at ~4.08 — DEM keeping exploration alive
- Running at ~3.3k sps (slower than FastSAC's ~26k due to JIT warmup phase)

**Not yet implemented:** Population diversity (per-env β scaling). DEM weights compute without β for now.

### FastDSAC tuning — three runs on CheetahRun

**Run 1 — target_entropy=0, no β:**
Peaked at **509** eval @ 21M steps, plateaued at ~490. Alpha stayed healthy at ~0.65 (not collapsed). Entropy ~4.0. The Gaussian critic and DEM are working — big improvement over FastSAC's 375. But still well below FastTD3's 880.

**Run 2 — target_entropy=-3, with β:**
Added population diversity β and lowered target entropy to -3.0 (half of -dim(A)=-6). Worse: only reached **401** @ 33M steps and still climbing slowly. Alpha collapsed to 0.012 — same failure mode as FastSAC. Target entropy -3.0 is too easy to satisfy with 6-dim actions, so alpha decays to near-zero and exploration dies.

**Run 3 — target_entropy=0, with β (best of both):**
Reverted target_entropy to 0, kept population diversity. Running now.

**Key finding:** Target entropy is the critical hyperparameter for SAC-family at scale. Any negative value risks alpha collapse on low-dim tasks. The paper's choice of 0 is deliberate — it maintains exploration pressure indefinitely. Negative target entropy means "be this deterministic," which is counterproductive for entropy-based exploration.

## Lessons
- **FastSAC (C51 + SAC) is a known underperformer vs FastTD3** — the FastDSAC paper documents this as a baseline. Alpha collapse + C51 quantization artifacts + uniform entropy waste. Need continuous distributional critic + dimension-wise entropy modulation (FastDSAC) for competitive results.
- **Network capacity matters for distributional critics** — (256,256) scored 335, (512,512) scored 375. FastTD3 used (512,512) from the start.
- **Always create proper presets for new algo variants** — FastSAC reused SAC presets with wrong network size. Created `get_fast_sac_preset()` to fix this.
- **Eval JIT can OOM late in training** — lazy JIT compilation of eval env.step allocates new CUDA graphs when GPU memory is full from training. Pre-compile at startup via `warmup_eval()`.
- **Research before tuning** — 5-minute literature search revealed FastSAC's plateau is a documented limitation, not a bug to fix. Same lesson as PPO on HumanoidRun.
