## RewardSpec refactor

Extracted inline `_get_reward()` into composable `RewardSpec` — list of `RewardTerm(name, fn)` tuples iterated by `compute_rewards()`. Returns unweighted dict; `step()` applies weights as before. Zero behavior change.

- Go2 Warp Joystick: 17 terms
- Go2 MJX Joystick: 16 terms (no base_height)
- Bongo Board Handstand: 9 terms (inline expressions, no helper methods)

**Why:** DIAYN needs to swap reward = discriminator output. With RewardSpec, that's `env._reward_spec = [RewardTerm("discriminator", disc_fn)]` — one line, no env fork. Also makes reward experimentation cheaper (bongo board went through multiple iterations).

## ObsSpec refactor

Extracted inline `_get_obs()` into composable `ObsSpec` — list of `ObsTerm(name, fn, noise_scale)` grouped by "state" (policy) and "privileged_state" (critic). `compute_obs()` iterates groups, applies per-term noise, hstacks per group. `IncludeGroup("state")` lets privileged state include the full policy obs as prefix.

- Go2 Warp: replaced 81 lines → 46 lines
- Go2 MJX: replaced 94 lines → 46 lines
- Bongo: replaced 90 lines → 47 lines (with conditional board_state terms)

**Why:** DIAYN skill vector = `env._obs_groups["state"].append(ObsTerm("skill_z", ...))`. Vision pixels = add `"pixels"` group. An undergrad can read the obs spec and know exactly what the policy sees.

137 CPU tests pass. GPU tests deferred (bongo training running).

## Bongo handstand training iteration

### Eval OOM fix
Eval loop was a Python for-loop calling `env_step` each iteration — same pattern as the "Warp OOMs in Python loops" lesson. Converted to `lax.scan` with per-step carry (returns, done flags, Q diagnostics). Fixes the recurring eval OOM at 512 envs.

### Arm/calf termination
Robot was leaning on calves/thighs for stability instead of balancing on toe tips. Named all front leg collision geoms in vendored go2.xml (`FL_hip_col`, `FL_thigh_col`, `FL_calf_upper`, `FL_calf_lower`, same for FR). Added 8 contact sensors (arm×board). Only foot spheres (FL, FR) may touch the board.

### Cost-based reward redesign (Run C)
Replaced exp-based rewards (which saturate near 1.0) with normalized quadratic costs:
- Survival (+10) is the ceiling, only positive term
- Each cost normalized to [0,1]: orientation/4, tilt/0.5, com/0.1, height/0.1, roller/0.05
- Weights = relative importance, directly comparable
- Negative rewards allowed — bad-but-alive is worse than dying
- Per-step perfect: 0.20, episode max: 50
