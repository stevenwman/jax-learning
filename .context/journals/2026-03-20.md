# 2026-03-20 — Codebase Refactor: Shared Training Utilities

## What we did

### Refactored all 6 train scripts to use shared utilities

Created `jax_rl/training/` module with 5 utility files, then refactored all train scripts to use them.

**New shared modules:**
- `checkpointing.py` — `save_checkpoint()`, `load_checkpoint()`, `load_actor_for_inference()`. Replaces 6 copies of `_save_checkpoint()`.
- `episode_tracker.py` — `EpisodeTracker` class. Replaces the 7-line episode reward tracking block duplicated 6 times.
- `env_setup.py` — `make_envs()`, `make_identity_norm_state()`. Replaces 6-line env creation + eval env setup.
- `metrics_logger.py` — `log_training_step()`, `make_metrics_row()`. Replaces stdout print + CSV row construction. Supports per-algo extra metrics via `extra_fields` param.
- `eval_runner.py` — `maybe_eval_and_checkpoint()`, `final_eval_and_checkpoint()`. Replaces eval trigger + checkpoint save blocks.

**Line count comparison:**

| | Before | After |
|---|---|---|
| Train scripts total | ~2,400 lines | 1,511 lines |
| Shared utilities | 0 | 431 lines |
| Total | ~2,400 | 1,942 |
| Duplication | 35% (~710 lines) | ~0% |

Individual script sizes: off-policy scripts ~230-240 lines (from ~400), PPO 321 lines (from 443).

**Verification:**
- All 6 scripts run successfully with short training (200k-500k steps)
- All 7 checkpoint tests pass
- No algo files modified — only training infrastructure changed

**Design decisions:**
- PPO uses shared utilities less than off-policy scripts — its training loop is fundamentally different (iteration-based, rollout collection, obs normalization, GAE). The eval/checkpoint calls were adapted but PPO still calls `evaluate()` directly with a wrapper function for obs normalization.
- `extra_fields` and `extra_keys` params on logging functions handle per-algo metric differences without subclassing. SAC passes `[("Ent", "entropy", ".3f"), ("Alpha", "alpha", ".4f")]`, TD3 passes nothing, FastDSAC passes `q1_var`.
- Argparse blocks stay per-script — not worth abstracting for 6 scripts with different CLI flags.

### record_video.py — now algo-agnostic

Rewrote to support all 6 algos automatically. Reads `meta.json` from checkpoint, reconstructs the correct algo for `select_action`, loads actor params via `load_actor_for_inference()`. No per-algo branches — one `_build_select_action()` function that dispatches based on `meta["algo"]`.

Tested with SAC and TD3 checkpoints. PPO uses a wrapper for obs normalization (same as before).

### Literature mismatch audit — massive config disparities found

Dispatched agents to compare our FastTD3/FastSAC/FastDSAC configs against the actual paper source code (holosoma repo for Seo et al., paper Table 1 for FastDSAC). Found critical mismatches in every algo. Full report: `.context/FAST_ALGOS_LIT_MISMATCH.md`.

**FastTD3/FastSAC (vs holosoma source code):**
- tau: 0.005 → **0.125** (25x difference, caused NaN at 31M steps on HumanoidRun)
- Network: flat (512,512) → **tapered 3-layer** (actor 512→256→128, critic 768→384→192)
- Activation: ReLU → **SiLU/swish**
- C51: 51 atoms → **101 atoms**, v=[-10,150] → **[-20,20]**
- Policy delay (FastSAC): none → **4** (actor updates every 4th critic update)
- LR schedule: cosine decay → **constant** (paper doesn't decay)
- Grad clipping: 1.0 → **disabled** (paper: max_grad_norm=0)

**FastDSAC (vs paper Table 1):**
- Buffer: 1M → **51K** (paper uses tiny buffers)
- Batch: 8K → **32K**
- Alpha init: 1.0 → **0.001**
- Min buffer: 25K → **1K**

### Config fixes applied

All mismatches fixed. Also added:
- `critic_hidden_dim` field to all off-policy configs (SAC, TD3, FastTD3, FastSAC, FastDSAC) — actor and critic can have different network sizes
- `grad_clip_norm` field to all off-policy configs — gradient clipping is now configurable, not hardcoded
- `policy_delay` field to SACConfig — for FastSAC's TD3-style delayed actor updates
- Fixed vanilla SAC ignoring `alpha_init` config field

### FastTD3 HumanoidRun — NaN'd at 31M (wrong tau)

Ran FastTD3 on HumanoidRun with the old config (tau=0.005, flat networks, ReLU). Reached 395 peak eval then NaN'd at 31M steps — Q went from 12.34 → NaN in one step. Classic divergence from slow target update at high UTD ratio. The paper's tau=0.125 prevents this.

### OOM root cause found — MuJoCo Playground recompiles identical JIT functions

Ran Test A from the OOM investigation: `JAX_LOG_COMPILES=1` over 30M steps of FastTD3.

**Finding:** 2 recompilations per minute at steady state. `jit(while)` (MJX contact solver) and `jit(scan)` (substep loop) recompile with **identical argument signatures** — 62 compilations each, 1 unique signature. JAX is recompiling the same function repeatedly.

Over 100M steps (~120 min), this accumulates ~480 CUDA command buffers that exhaust GPU driver memory. This is upstream MJX behavior, not our code.

**Fix:** `XLA_CLIENT_MEM_FRACTION=0.7` leaves enough headroom for the accumulation. Proven over a full 100M step run.

### Sample-time obs normalization — implemented and verified

Discovered the FastTD3 paper (holosoma) normalizes obs **at sample time** (after sampling from buffer), not pre-storage like our earlier attempt that exploded. Implemented as a modular `--obs-norm` toggle on all 5 off-policy scripts.

**Key design:** Raw obs stored in buffer. After `buffer.sample()`, normalize `obs` and `next_obs` with current running stats using eps=1e-2 (paper's value, prevents near-zero variance blowup). Also normalize obs for `select_action()` during collection so the actor sees consistent distributions.

**Results on CheetahRun SAC @ 500k steps:**

| Config | Eval |
|---|---|
| obs_norm=False (default) | 353 |
| **obs_norm=True** | **455 (+29%)** |

Verification:
- 5 unit tests pass (config fields, eps behavior, identity passthrough)
- Checkpoint resume preserves norm_state
- record_video.py loads obs-norm checkpoints correctly

## Lessons
- **The refactor plan was detailed enough to execute mechanically** — every block mapped to a destination, every function signature specified. No design decisions needed during implementation. This is the value of planning before coding.
- **PPO doesn't fit the off-policy template cleanly** — it uses iteration-based logging, obs normalization, rollout buffers. The shared utilities help with checkpointing and env setup but the training loop itself can't be shared. This validates the "shared utilities, not Trainer class" decision.
- **`load_actor_for_inference()` is the key abstraction for algo-agnostic tooling** — both `record_video.py` and any future eval/deployment script just need meta.json + actor_params.npy. No orbax, no optimizer state, no algo-specific imports at the call site.
- **Always verify configs against paper source code, not just the paper text** — the paper text says "lr=3e-4, Adam" but the source code reveals tau=0.125, SiLU, tapered 3-layer networks, policy_delay=4, and many other details not mentioned in the paper. The holosoma repo was the authoritative source.
- **tau=0.125 is not a typo — it's essential for high UTD ratio** — with 8 gradient steps per env step, the online network changes rapidly. tau=0.005 (standard SAC/TD3) can't track this, causing Q divergence. tau=0.125 means the target updates 25x faster, keeping it close to the online network.
- **Pre-storage vs sample-time obs normalization is a critical distinction** — normalizing before storing in the replay buffer causes stale statistics → exploding values. Normalizing after sampling with current stats is safe. The paper uses eps=1e-2 (not 1e-8) to prevent near-zero variance blowup at env reset. This single change gave +29% on CheetahRun SAC.
- **Always check the paper's source code for normalization details** — the paper text just says "obs normalization=True" but the source reveals it's sample-time with separate actor/critic normalizers and large eps. The mechanism matters more than the toggle.
