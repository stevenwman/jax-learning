## Glossary Auto-Linking System

Built a mkdocs hook (`docs/scripts/glossary_links.py`) that:
1. Reads `docs/glossary.md` headings → builds term→anchor map
2. Reads `docs/includes/term_links.yml` → non-glossary terms (PPO→api/algos.md#ppo, etc.)
3. On each page, replaces first occurrence of each term with a subtle link
4. Skips code blocks, headings, existing links, and the target page itself
5. Uses `.gl` CSS class — inherits text color, light underline, highlights on hover

# 2026-04-09 PM — Training Script Cleanup + DR Migration Completion

## Summary

Cleaned up the training script architecture after the DR v2 work. Two major pieces:
1. **Per-algo training scripts + 4 shared utilities** (morning)
2. **Legacy DR path + syncd mode removal** (night)

Net: -1,321 lines across the cleanup commit, much cleaner separation of concerns.

## Part 1: Training Script Cleanup

After 2 senior SWE reviews flagged the conditional explosion in training scripts, implemented 4 utilities:

### ObsPipeline (`jax_rl/training/obs_pipeline.py`)
Stateless class encapsulating obs extraction, normalization, buffer setup, frame stacking, and batch normalization. Built once from config, eliminates ~8 branches per training loop.

Methods: `get_obs`, `get_critic_obs`, `update_stats`, `normalize_for_action`, `normalize_batch`, `make_buffer`, `make_buffer_with_critic`, `make_obs_norm_fn`, `init_norm_state`.

14 unit tests.

### TrainContext (`jax_rl/training/train_context.py`)
Dataclass bundling the 10+ args that were threaded through eval/checkpoint. `maybe_eval_and_checkpoint` went from 19 args to 9. Fields: cfg, algo_cfg, algo_name, ckpt_dir, obs_dim, action_dim, metrics_log, ckpt_mgr, resume.

### Algo-owned policy_delay
Moved TD3/FastTD3 `policy_delay` metric carry-forward from the training scripts into the algo's `update()`. Added `last_actor_loss` field to TrainingState. Removed 6 lines of branching per TD3 training script.

### CLI override utility (`jax_rl/training/cli_utils.py`)
Declarative `apply_cli_overrides(args, cfg, algo_cfg)` replaces 15-25 lines of `if args.X is not None` per script. 24 tests.

### Wire-up results
- All 4 standalone scripts (train_sac, train_td3, train_fast_sac, train_fast_td3) refactored
- 234 lines removed from training scripts
- 42 new unit tests pass
- All 277 existing tests pass
- Smoke tested: SAC, TD3, FastSAC, FastTD3 on CartpoleBalance + Go2 FastSAC with DR per_step

## Part 2: Legacy DR Path + Syncd Mode Removal

The DR v2 migration was incomplete — we built DomainRandWrapper but never deleted the old path. 11 files still referenced `--domain-rand`, `go2_randomize.py`, `bongo_randomize.py`, `DomainRandomizationVmapWrapper`. Plus syncd mode had integration problems and was never used.

Cleaned all of it in one pass:

### Deleted
- `jax_rl/envs/locomotion/archive/` (go2_randomize.py, bongo_randomize.py, plus MJX archived envs)
- `DomainRandomizationVmapWrapper` class from `training.py`
- `_step_syncd` and `batch_reset` methods from `DomainRandWrapper`
- `--domain-rand` CLI flag from all training scripts
- `domain_rand` field from `TrainConfig`
- `syncd` from `reset_mode` choices (now just `["legacy", "per_step"]`)
- `--reset-mode syncd` / `DR syncd mode` tracking code from training loops
- `BOOL_CFG = {"domain_rand"}` from cli_utils.py
- Legacy DR test from test_go2_warp_env.py

### Result
DR now lives in exactly 2 places:
1. `jax_rl/envs/wrappers/domain_rand.py` — DomainRandWrapper
2. Each env's `get_domain_randomization_spec()` method — the specs

One code path. Two reset modes: `legacy` (default, simple envs) or `per_step` (Go2-style, fresh reset + auto DR if env has specs).

### Training script changes
- `train_fast_sac.py`, `train_sac.py`, `train_td3.py`, `train_fast_td3.py`, `train_offpolicy.py`, `train_flashsac.py`: removed `--domain-rand`, syncd tracking, batch_reset calls
