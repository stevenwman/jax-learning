### What the contract carries
`meta["control"]` (17 fields) and `meta["obs_schema"]` written at
`save_checkpoint` time:
- `Kp/Kd/action_scale/policy_dt/physics_dt`
- `default_pose_policy/sdk` (sourced from `self._default_pose` →
  joystick uses `keyframe("home")`, bongo uses `keyframe("handstand")`)
- `policy_joint_names`, `sdk_joint_names`
- `policy_to_sdk`, `sdk_to_policy` index arrays
- `contact_mode`, `torque_speed_model`, `impl`

### Deploy consumption
- `Go2Interface(control_meta=...)` reads everything from meta; falls
  back to `go2_constants.py` with a loud warning if absent.
- `ObsBuilder.from_checkpoint(strict=True)` for real-arm path; refuses
  partial legacy `control` blocks (catches the `KeyError`-later-in-
  `send_action` failure mode early).
- `deploy_go2.py` reads `policy_dt` from meta (so a 25/100Hz ckpt
  doesn't run at the constants 50Hz by accident).
- Pre-arm sanity prints raw quat/accel/gravity/tilt and warns on
  `sign(accel_z) == sign(gravity_z)` — the IMU/quat-frame mismatch
  observed in `.temp/obs_prinout.txt`.

### Codex-review iterations caught
1. Strict mode silently accepting partial legacy control → would
   `KeyError` later in `robot_interface.send_action`.
2. `get_control_metadata` hardcoded `keyframe("home")` — wrong for
   Bongo (uses `keyframe("handstand")`).
3. `Go2WarpJoystickUnitree` overclaiming "Unitree-contract" — name kept
   (mid-flight training) but docstrings honest about what's matched
   (action_scale 0.25, no accel) vs not (no per-term gyro/jvel scaling).
4. `deploy_go2.py` ignoring meta `policy_dt`.

All 4 fixed in `ee4f149`. Tests added:
- `test_obs_builder_strict_refuses_partial_control_block`
- `test_bongo_metadata_uses_handstand_pose_not_home`
- 11/11 e2e + 18/18 deploy/checkpoint regression pass.

### Loud-on-Go2 in save_checkpoint
`save_checkpoint` raises (not warns) if a Go2 env can't stamp
`obs_schema` or `control`. This is the exact silent-failure mode that
bricked deploys 2026-04-10 → 2026-04-24.

## Part B — Action_scale was the bottleneck

Ran the new contract through three FastSAC trainings to validate
sim2real-aligned settings.

### Setup
- env `Go2WarpJoystickFlatNoAccel` (45d obs, no accel) — closer to
  unitree_rl_lab Go2 deploy contract than the legacy 48d.
- num_envs=1024, obs_norm on, default reward config.

### Runs

| Run | env | scale | total | best | final | std |
|---|---|---|---|---|---|---|
| seed7001 v1 | `Go2WarpJoystickUnitree` | 0.25 | 20M | 220 | 197 | ±67 |
| seed7001 v2 (resume) | same | 0.25 | 100M | 273.5 | 242.5 | ±58 |
| seed7002 | `Go2WarpJoystickFlatNoAccel` | **0.5** | 50M | **288.1** | 283.3 | **±5.9** |

### Findings
1. **action_scale=0.25 plateaued at 273** even after 100M steps. Eval
   variance stayed wide (±58) — policy never settled on a clean gait.
2. **action_scale=0.5 saturated by 28M** at 288. Eval variance dropped
   to ±5.9 — policy is consistent, not lucky.
3. The 0.25 policy could not track higher velocity commands (vx > 1.0)
   because halving action_scale halves max joint delta per step, so
   peak achievable speed drops. Confirmed by recording the same policy
   with `--cmd-max 1.0 1.0 1.2` — tracking improved.

### Historical comparison
| Run | Total | Best |
|---|---|---|
| seed 6001 (FastSAC, 48d) | 21.9M | 276.5 |
| seed 7000 (FastSAC, 48d) | 50M | 279.1 |
| seed 8001 (FastSAC, 48d) | 20M | 280.1 |
| seed 9000 (FastSAC, 48d) | 20M | 281.9 |
| v16 curriculum (48d) | 20M | 290.3 |
| **seed 7002 (FastSAC, 45d)** | **50M** | **288.1** |

Dropping accel didn't cost performance. Action scale matters more.

### What this means for hardware
- `seed7002` ckpt is the deployable artifact:
  `checkpoints/20260428_085344_fast_sac_go2warpjoystickflatnoaccel_seed7002/best`
- 45d state matches deploy `ObsBuilder` default schema after
  schema-from-checkpoint loads it.
- Full deploy contract stamped (17 control fields).
- `ObsBuilder.from_checkpoint(strict=True)` loads cleanly.
- Pre-arm sanity ready to catch quat-frame bug from `.temp/obs_prinout.txt`.

### Recording tools added
- `--varied-cmds N`: resample uniform velocity command every N steps
  (50 steps = 1s at 50Hz).
- `--cmd-max VX VY YAW`: symmetric ranges for the sampler. Useful for
  capping linvel during eval to isolate action_scale vs tracking.
- `--cam-distance D`: closer free-camera tracking (3.0 vs default 6.0).
