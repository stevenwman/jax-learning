## PPO bongo handstand runs

### PPO2 — config C baseline (50M)
Continued from yesterday's launch. Config C (cost-based rewards), 512 envs, ep=250, eval every 50k eps.

Best eval **23.7 ± 6.9** [13, 37] at 45M steps. Training returns reached ~18. Still climbing at end of run but slow.

Key dynamics: entropy collapsed from 7.8 → -0.89 over training. Policy became near-deterministic — all envs got identical returns (train return std ≈ 0). Balances 1.5-3s then falls.

### PPO3 — added torque + velocity penalties (100M)
Added `joint_vel_cost` (normalized joint velocity squared, weight -1.0) and bumped `torque_cost` from -0.5 → -1.0. Ran 100M steps.

**Peaked at 15.9 at 28M then regressed to ~11.** The extra penalties made the robot calmer but worse at balancing. The policy optimized for "don't move much" rather than "stay balanced." Second 50M steps added nothing — flat at 10-11.

**Lesson:** Regularization penalties can be counterproductive on hard balance tasks. The optimal strategy may require aggressive corrective actions that torque/velocity penalties suppress.

## Domain randomization research

Researched MuJoCo contact friction handling for bongo board DR:

- **Friction combining:** element-wise max of two contacting geoms (equal priority). Floor has `priority=1` which overrides.
- **`<pair>` elements:** bypass combining entirely — cleanest way to set per-contact-pair friction. `mjx.Model` exposes `pair_friction` (N,5) for batched DR.
- **Community practice:** Isaac Lab, WTW, legged_gym all randomize friction [0.3, 1.5]. Nobody randomizes solref/solimp (contact stiffness/damping).
- **Plan:** Add `<pair>` elements for feet-board contacts, randomize tangential friction per-pair. Also randomize board mass, robot mass/motor strength.
