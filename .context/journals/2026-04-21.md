# 2026-04-21 — ContractionPPO port + on-policy collect extraction

Ported Zinage et al. ContractionPPO (Caltech, https://contractionppo.github.io/) onto jax-learning PPO. End-to-end validation on `Go2BongoHandstandContraction` confirms contraction learning (penalty drops 60% in 2 iters). Partial on-policy loop extraction shipped as infrastructure.

## Key insight from ref code reading

Paper is vague about how they handle the dynamics Jacobian `∂f/∂x` needed for the contraction condition. Reading `/tmp/cppo/contraction_ppo.py:271-333` revealed they **sidestep it entirely**:

- State `x` is a low-dim constraint residual `c = obs − desired` (handstand: 3-dim gravity residual).
- Time-derivative `ẋ` is **supplied as an env observation** (`contraction_c_dot`), computed from sim-provided body accelerations + analytical kinematics (`ġ_b = −ω × g_b`, `q̇ = ½Ω(ω)q`).
- `V̇ = ∇_x V · ẋ` uses `torch.autograd.grad` on the V network — no differentiable simulator needed.
- Paper's `x = [c; e]` formulation with `e = state − policy_output` is **commented out in ref code**; `x = c` only (ref:307-308).
- PPO loss does NOT include contraction term (ref:661 commented). Policy influence is via **reward augmentation** `(ε − ReLU(V̇ + αV + ε)) * penalty_coef` (ref:908).

This means "contraction-theory RL" here is functionally just an aux metric network generating a Lyapunov-like shaping reward. Faithful to ref-as-implemented but strictly weaker than ref-as-described theory.

## Code review pattern — diminishing returns after 4 rounds

Plan review loop: 4 independent subagent reviews caught ~25 issues cumulatively:
- Round 1: ~10 structural (test dir, preset absence, reward timing off-by-one)
- Round 2: ~9 (per-minibatch metric freq, double-backward cost, dict vs NamedTuple for extras)
- Round 3: ~5 new (`value_and_grad` tuple unpack, `env.reset` wrapped-key mismatch, `constraint_coef` dead field)
- Round 4 (parallel pair): ~8 but half overlapping — verdict divergence (A: NEEDS_REVISION, B: APPROVE_WITH_MINOR_FIXES). The 3 A-blockers were real but agents flagged same plumbing issues with different emphasis.

Decision: stop reviewing after round 4. Each round found novel issues but rate was slowing. Remaining bugs would be caught faster at commit boundaries against actual code than in plan prose.

Lesson: multi-round plan review is valuable for cross-framework ports (PyTorch ref → JAX target has many interface boundaries) but has diminishing returns past round 3. Parallel reviewers mostly overlap by round 4.

## Architectural decision: fork vs merge

For `PPOContraction`, chose **fork** (`jax_rl/algos/ppo_contraction.py`, 372 lines) over merging into `ppo.py`. Reasons:
- Baseline PPO stays byte-identical — ablations provably safe (test `test_update_without_contraction_matches_ppo_baseline_actor` confirms bit-identity of actor/critic params after one update against both PPO and PPOContraction with contraction=None).
- Research-stage experimental feature — likely to iterate (spectral norm, lyap regularization, etc.) — keeping diffs scoped to one file is easier.
- 70% duplication acceptable for isolation.

If contraction validates → revisit merge.

For training script: **partial extraction** (`make_collect` factory only). Full on-policy loop extraction to mirror existing off-policy pattern is separate work, scoped in [.superpowers/plans/2026-04-21-onpolicy-loop-extraction.md](.superpowers/plans/2026-04-21-onpolicy-loop-extraction.md) but deferred.
