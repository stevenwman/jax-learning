# Documentation Site Agent Prompt

---

You are maintaining the public docs site for **jax-learning**, a JAX-based RL framework for the Unitree Go2 quadruped.

**Live site:** https://stevenwman.github.io/jax-learning/
**Auto-deploys** on push to main via `.github/workflows/docs.yml`.

## Before you start

1. Read the agent handoff: `.context/references/docs_site.md` — this has the full site structure, architecture decisions, commands, how-to guides, and gotchas.
2. Read the project overview: `.context/AGENT_HANDOFF.md`
3. Read existing docs pages before editing — understand what's there before changing it.

## Key facts

- `uv run python` (not python3)
- No Co-Authored-By in commits
- MkDocs + Material theme (**no mkdocstrings** — all API pages are hand-crafted)
- Install docs deps: `uv sync --group docs`
- Build: `uv run mkdocs build`
- Serve: `uv run mkdocs serve`
- **API pages are hand-written Markdown**, not auto-generated from docstrings. After changing code signatures or config defaults, update `docs/api/*.md` manually.

## Architecture decisions you must follow

### Hand-crafted API pages
All `docs/api/*.md` pages use summary tables, structured sections with import lines, field tables, and definition-list methods. Do NOT add `::: module.path` mkdocstrings directives — they were removed because they produced unreadable walls of text.

### Abbreviation tooltips
`docs/includes/abbreviations.md` defines ~25 terms (UTD, GAE, MLP, MJCF, PD gains, etc.) that get hover tooltips site-wide via `abbr` + `pymdownx.snippets`. When introducing new jargon, add it here — every page gets tooltips automatically.

### Glossary cross-links
Key pages link first-use jargon to `docs/glossary.md` anchors (e.g., `../glossary.md#utd-ratio-update-to-data`). Link first use only, not every occurrence.

### CSS
`docs/stylesheets/extra.css` has separate One Dark / One Light syntax highlighting, API doc visual separation, video grid, mobile table scroll, and WCAG AA contrast fixes. Light-mode comments must be at least `#717580`.

## How to add a new algorithm

1. Add `## AlgoName` section to `docs/api/algos.md` (constructor, methods, summary table row)
2. Add `## AlgoConfig` section to `docs/api/configs.md` (field table)
3. Add network blocks to `docs/api/networks.md` if applicable
4. Add parser to `gen_cli_reference.py`, regenerate
5. Add presets to `gen_env_presets.py`, regenerate
6. Update `docs/getting-started/concepts.md` (algo count + table)
7. Update `docs/index.md` (algo count in features)
8. Update `docs/reference/architecture.md` (mermaid diagram + config list)
9. Add abbreviation to `docs/includes/abbreviations.md` if new jargon
10. `uv run mkdocs build` to verify

## Review process

Use the 4-persona parallel review pattern in `.context/references/docs_review_pattern.md`:
1. **High schooler** — accessibility, jargon, where they'd give up
2. **Undergrad CS** — factual accuracy, cross-reference everything against code
3. **PhD researcher** — code correctness, benchmark rigor, adoption readiness
4. **Frontend engineer** — visual design, CSS, navigation, contrast

Dispatch all 4 as background Opus agents. Compile results into prioritized action list (quick / medium / large).
