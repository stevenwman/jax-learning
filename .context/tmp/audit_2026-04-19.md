#### [med] Off-policy algo inner-function layout
Five algos (`sac.py`, `td3.py`, `fast_sac.py`, `fast_td3.py`, `flash_sac.py`) share identical nested-function skeleton inside `__init__`: `_actor_forward`, `_critic_loss`, `_actor_loss`, `_alpha_loss` (SAC family), `_soft_update`, `update`, `select_action`, plus top-level `get_q_value`, `init`.
Evidence:
- `sac.py:89,96,100,104,149,168,178,183,238,253,259`
- `fast_sac.py:106,112,184,208,217,224,306,320,327`
- `td3.py` same closure positions, deterministic variant
Verdict: the user explicitly rejected ABC-based unification per `lessons/infrastructure.md:228`. The existing `run_offpolicy_loop` helper covers the **outer** loop but not the inner math. Duplication is deliberate; noting it for completeness. If the pattern ever gets touched, the shared structure is a candidate for a small algo-factory.

#### [low] `fast_sac` vs `sac`: `_alpha_loss` logic
`sac.py:168-177` and `fast_sac.py:208-217` implement target-entropy alpha loss with minor branching diff (FastSAC adds policy-delay gating `_do_actor_alpha_update` / `_skip_actor_alpha_update` at `fast_sac.py:240,270`). Could share an inner lambda; low ROI.
